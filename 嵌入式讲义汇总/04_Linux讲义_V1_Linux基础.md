#### 4.1 设置静态IP地址（可不做）

虚拟机的IP地址默认是动态获取的，可能会随着网络环境的改变（换网线、换热点等）

而变化。

而我们使用远程工具连接虚拟机时，需要用到这个IP地址。

如果这个IP地址频繁改变，我们进行远程连接时，也需要频繁改配置，用起来会比较麻烦。

所以我们可以考虑给虚拟机设置一个固定的、静态 IP 地址，这样 IP 地址不会改变，用起来会更方便一些。

**但配置静态IP很容易导致虚拟机无法联网，考虑到大家一直在教室学习，网络环境不会频繁改变，所以也可以不设置静态IP地址。**

#### 4.2 安装SSH

安装好之后，查看是否启动了守护进程（类似 Windows 上的服务）`sshd`：

```c
ps -elf | grep sshd
```

```c
4 S root 959 1 0 80 0 - 18076 - 09:30 ? 00:00:00 /usr/sbin/sshd -D
```

**注：显示的信息可能不一样，只要出现 /usr/sbin/sshd -D 即可。**

#### 4.5 XShell常用快捷键

使用XShell远程连接Linux服务器，打开一个会话，输入shell指令可以操作Linux系统。

一些比较常用的快捷键如下：

1. 方向键上下，表示查看指令的历史记录
2. Ctrl + A，表示将光标移动到最左端
3. Ctrl+ E，表示将光标移动到最右端
4. Ctrl + U，表示删除光标前的所有输入
5. Ctrl + K，表示删除光标后的所有输入
6. Ctrl +L，即刻情况当前会话窗口的所有内容，相当于输入指令clear
7. **Tab，自动补全命令或文件名等。**
8. 进入某个进程执行界面后：
   - a. **Ctrl + C：中断当前进程。**
   - b. **Ctrl + D：在输入时发送EOF。**

```c
sudo apt install vim # 安装vim
```

#### 5.1 检查Vim版本

首先检查一下Vim的版本号，检查一下是否是Vim 8.0及以上的版本。当然，现在Ubunbtu默认的都是8.0以上的版本：

```c
vim --version
```

输出的第一行一般就是Vim的版本号：

VIM - Vi IMproved 8.2 (2019 Dec 12, 编译于 Mar 14 2024 09:05:11)检查完Vim的版本号后，可以继续检查一下当前Vim是否支持python3，输入下列指令：

```c
vim --version | grep python
```

**若出现"+python3"这一选项表示支持，若出现"-python3"则表示不支持。**

## 02 Linux发展历史

### 1. 前言

从今天开始，我们要讲解Linux操作系统的相关知识概念，于是我们就有了一个基础的疑问：

什么是操作系统呢？

我们先从术语的角度来解释计算机操作系统：

计算机操作系统（Operating System，简称OS）

是一种管理计算机硬件资源，提供进程运行环境的**系统软件**，并且操作系统还作为用户和计算机硬件之间的接口。

通俗的说，操作系统作为一种中间层，对上层应用软件提供运行环境，对下层管理控制计算机的一切硬件资源。

如果你不甚理解这句话，也没有关系，在随后的课程内容中你会逐渐理解这句话。

在整个操作系统的发展历程中，Linux操作系统无疑具有举足轻重的地位。

从其诞生之初的1991年起：

Linux已经从最初林纳斯·托瓦兹（Linus Torvalds，Linux之父）的个人项目，演变成为支撑全球计算基础设施的核心力量。

在实际的应用中：

1. Linux是服务器端的霸主级操作系统
2. 在移动端，安卓（Android）同样基于Linux内核开发
3. 而且Linux的成功还促进了开源软件运动的兴起，为全球范围内的开源软件合作开发树立了标杆。

接下来我们的课程就要来深入学习一下Linux操作系统以及C语言相关的一些技术栈。

那么首先，我们先来大致了解一下Linux的发展历程。

### 2. Linux的诞生

**1960年代的Multics System：**

早期的操作系统为批处理操作系统，输入设备只有卡片阅读机，输出设备只有打印机。

程序员的编程是在读卡纸上进行的，通过打孔机进行打孔，打孔表示 1，没打孔表示0。

这样的操作系统缺陷很明显：如果计算机需要处理多个任务，那么后面的任务就需要排队执行，浪费了CPU的性能。

进入到1960年代初期麻省理工学院 (MIT) 开发了划时代的兼容分时系统 CTSS (Compatible Time-Sharing System)，它允许操作系统在多个任务之间来回切换，于是多个用户可以通过终端连接到主机，共享计算资源。

兼容分时操作系统的主要优势就在于：它让每个用户感觉是在独享主机的资源，在计算资源非常宝贵的年代，这是非常难得的。然而，即便是当时最先进的主机，也只能支持大约30个终端机，这还是有些不够的。

为了提升大型主机的资源利用率，并使更多用户能够同时使用这些资源，贝尔实验室（Bell Labs）、麻省理工学院和通用电器公司（GE）于1965年联合启动了Multics（Multiplexed Information and Computing Service，多路信息计算系统）计划。

Multics System是一种全面通用的分时操作系统，目标是让大型主机能够同时支持300多个终端机。然而到了1969年，由于项目进展缓慢和资金短缺，贝尔实验室认为Multics项目不可能成功，因此决定退出。

Multics 计划其实并不算失败，在后续它也取得了不俗的成就，并直到1980年代才完全被搁置终止。不过这个我们且按下不表，因为我们要讲另一个更加波澜壮阔的历史。

**1969年：Ken Thompson 发明了 Unics**1969年，贝尔实验室退出了宏大且复杂的Multics计划，Ken Thompson和Dennis Ritchie等曾参与该项目的工程师回到了贝尔实验室。由于比较空闲，这一年 Ken Thompson 写了一个游戏 —— 太空旅行 (Space Travel)。

然而，由于贝尔实验室当时仍在使用不太适合交互式使用的批处理操作系统，这款游戏在实际体验上并不理想。

机缘巧合之下，Thompson在实验室的库房里发现了一台被搁置的PDP-7小型计算机。

他决定将游戏移植到这台设备上。但移植过程中，他发现游戏在PDP-7上运行效率低下。这激发了Thompson对为这台机器编写新操作系统内核的想法。

恰好在同年的8月份，Thompson 获得了一个月的休假期，而且他的妻子孩子也回老家探亲了。于是 Thompson 就利用这一个月时间，以及他从 Multics 项目中获得的灵感，将庞大而复杂的 Multics System 做了大幅地简化。实验室的同事也因此戏称这个系统为Unics，寓意为更简洁的Multics。

Thompson在设计 Unics 系统内核时，有两个重要的思想：

1. **首先是“一切皆文件”原则。**所有的程序或者系统设备都可以被视为文件。
2. **其次是"高效简洁"的原则。**即程序应仅仅专注于有效地完成其既定目标。

这些理念后来被称为KISS原则 (Keep It Simple, Stupid)，这也是 "Unix 哲学"的根本原则。有一本著作叫《The Art of Unix》就是讲 Unix 的设计原则的。

**当然这一年还发生了一件大事，在地球另一端的——芬兰，Linux之父林纳斯（Linus Travalds）出生了。**

**1973年：Unix 系统内核正式诞生**由于 Thompson 写的 Unics 操作系统实在太好用了，在贝尔实验室内部广为流传，并且经过多次改版。

但是因为 Unics 是以汇编语言编写的，高度依赖硬件，而且当时计算机机器架构都不太相同，所以每次安装 Unics 系统，都要重新修改汇编代码，非常的不方便。

于是 Thompson 与 Dennis Ritchie 合计将 Unics内核用高级语言进行重写，从而提高操作系统的可移植性。他们先选择了 BCPL ，然后又尝试PASCAL，发现编译出来的内核性能都不是很好。

于是，两人 (主要是Dennis Ritchie) 决定自己开发一套新的语言：这就是大名鼎鼎的 C 语言。**C语言之父一般认为是Dennis Ritchie。**

1973年，Dennis Ritchie 用 C 语言重写了 Unics 的内核，随后发行出 Unix 的正式版本。

重写说起来简单，实际上并不是简单的汇编到C 语言的翻译，这里边包含了很多的发明和创造。比如，在此期间引入的 “pipe” (管道) 功能后来成为了 Unix 的一大优势。而管道的概念也是由贝尔实验室的 Douglas McIlroy (当时 Bell Lab 的主管) 发明的。

**1977年：Unix 的重要分支 BSD 诞生**1977年是Unix历史上的关键一年，这一年，Unix的一个重要分支——BSD（Berkeley Software Distribution，伯克利软件套件）诞生了。

Unix的早期版本由AT&T（美国国际电话电报公司）的贝尔实验室开发，贝尔实验室当时隶属于AT&T公司。Unix诞生之初，AT&T采取了相对开放的策略，允许学术界获取Unix的内核源码。这种开放的态度促进了Unix与学术界的紧密合作，尤其是与加州大学伯克利分校（UC Berkeley）的合作。

在这个过程中UC Berkeley的**研究生Bill Joy**获得了Unix的内核源码，并开始着手修改，以使其更适合自己的机器。

在此过程中，他增加了许多新的工具软件和编译程序。经过这些改进和增强，他最终将这个版本命名为Berkeley Software Distribution，简称BSD。BSD不仅是Unix的一个重要分支，也为后续的操作系统开发提供了众多创新和灵感。

值得一提的是，Bill Joy不仅因BSD成为计算机科学界的重要人物，他后来还参与创立了Sun Microsystems公司，进一步影响了整个计算机行业。Sun公司是Java编程语言的发明者，这同样是一个计算机领域举足轻重的编程语言。

**1979年：AT&T 发布支持 x86 架构带商业版权的 System V 第七版**1979年是Unix历史上的一个里程碑年份，这一年，AT&T发布了支持x86架构的个人计算机（PC）操作系统System V第七版，为Unix操作系统的商业发展开辟了新的道路。

由于 Unix 的高度可移植性与强大的性能，加上当时没有版权纠纷，很多商业公司开始了 Unix 操作系统的开发。他们将 Unix 操作系统移植到自家的硬件平台上，从而推出适合自家硬件平台的 Unix 系统，例如 AT&T 的 System V、IBM 的 AIX，HP 的 HP/UX 等等...

操作系统内核 (Kernel) 必须跟硬件密切配合，因为操作系统需要管理硬件资源。早期生产计算机硬件的公司还没有统一的标准，每一个公司生产的硬件都不相同。因此每一个公司必须为自己的计算机硬件开发合适的 Unix 系统。而且，每一个公司开发出来的Unix 系统是不能在其它硬件架构下工作的。另外，由于没有厂商针对个人计算机设计Unix 系统 (因为那时个人计算机并不流行)。因此，在当时是没有支持个人计算机的Unix 系统的。

直到 1979 年，AT&T 推出了 System V 第七版，这个情况才有点改善。这一版最主要的特色是：可以支持 x86 架构的个人计算机。也就是说个人计算机终于可以用上 Unix 系统了。

到了80年代初，曾经风光无限的AT&T公司开始被美国当局进行反垄断调查并最终被强制拆分，出于公司生存考虑，AT&T公司开始将Unix操作系统进行商业化，也就是收费并且不再提供源代码。

AT&T公司的这一操作，瞬间制造了 Unix 业界的紧张气氛，同时也点燃了商业纠纷的战火。

这又是另一个波澜壮阔的历史，感兴趣的同学可以自行查看相关资料。目前存活下来，且还在被商业使用的大概就只有 System V 和 BSD 这两系了。

**1984年：Minix 系统，GNU 项目**1984年，在Unix界发生了两件具有深远影响的事件：Minix系统的诞生和GNU项目的启动。

AT&T的System V第七版的版权声明对学术界造成了巨大的影响，尤其是影响了教授操作系统的教育工作者。因此，Andrew Tanenbaum教授，一位在荷兰阿姆斯特丹自由大学的计算机科学家，决定编写一个类Unix的操作系统，用于教学目的。

为了避免版权纠纷，Andrew Tanenbaum 完全不看 Unix 的内核源码，编写了一个完全Mini 版本的 Unix 系统内核，所以被称为 Minix。

1986 年，Minix完成编写任务，并于次年出版书籍《Operating Systems: Design and Implementation》(书的附录中有 Minix 的源码)。Tanenbaum 还有另一本很出名的书籍《Modern operating systems》。

Minix 并不是免费的，必须通过磁盘磁带进行购买。不过售价非常便宜，而且还会随赠Minix 源码。

Minix 系统收到了广大用户的欢迎，很多用户强烈要求 Andrew Tanenbaum 对 Minix 进行改进。但是 Andrew Tanenbaum 教授只是把 Minix 定位在教育用途上面，无心对Minix 进行持续开发。这才有了后面 Linux 的故事...

在 Andrew Tanenbaum 教授开始编写 Minix 的1984年，一个伟大的计划正在悄然诞生，这就是日后和 Linux 双剑合璧一起改变世界的GNU 项目。

GNU 项目，是一个自由软件集体协作项目，它是由 MIT 的 Richard Mathew Stallman (RMS) 发起的，它的目标是创建一套完全自由开源、免费的 Unix 操作系统。GNU 是"Gnu is Not Unix" 的递归缩写。

1985 年，为了避免 GNU 所开发的自由软件被其他人所利用而成为专利软件，所以Richard Stallman 与律师草拟了有名的通用公共许可证 (General Public License, GPL)，并且称呼为 copyleft (相对于专利软件的 copyright)。

GNU 项目领导了计算机产业轰轰烈烈的自由软件运动，该项目也开发出了许多高质量的免费软件，其中包括有名的 Emacs 编辑系统、Bash Shell 程序、GCC 系列编译程序、GDB 调试程序等等。

不过，对于 GNU 的最初构想『建立一个自由的 Unix 操作系统』来说，有这些优秀的程序仍然是不够的，因为，当时并没有『自由的 Unix 内核』存在。所以这些软件只能在那些有专利的 Unix 平台上工作，直到 Linux 的出现。

GNU 项目组曾经致力于开发一个名为**"GNU Hurd"**的微内核架构的类Unix操作系统内核，但由于微内核架构实现过于复杂且开发资源不足，始终没有开发成功。待到Linux内核诞生，Hurd就被完全搁置了且最终也没有开发成功。

**1988年：POSIX 标准诞生**POSIX 是 Portable Operating System Interface 的缩写，而 X 表示其对 Unix API 的传承。POSIX 这个名称是由 Richard Stallman 向 IEEE 协会提议的一个名字，它最初的名字为 IEEE-IX。

POSIX 标准源于 1985 年的一个项目，该项目旨在保证各个操作系统之间的兼容性。也就是说，如果两个系统都遵循 POSIX 标准的话，那么在一个系统上能够运行的软件，在另一个系统上也可以运行。1988年，发布了 POSIX 标准的第一个版本。

Linux 基本上逐步实现了 POSIX 兼容，但并没有参加正式的 POSIX 认证。微软的Windows NT 声称部分实现了 POSIX 标准。

**1991年：Linux 0.0.2 版发布**1988 年，Linus Torvalds 进入了赫尔辛基大学，并选读了计算机科学系。在读大学本科期间，他接触到了 Unix 系统。

当时整个赫尔辛基只有一部最新的 Unix 系统，同时仅提供 16 个终端 (Terminal)连接。

早期的计算机仅有主机具有运算功能，Terminal 仅负责提供 Input/Output 而已。

这种情况，实在很难满足 Linus 的需求。不久之后，他就知道有一个类似 Unix 的操作系统，并且与 Unix 完全兼容，还可以在 Intel 386 机器上面运行 —— Minix。Linus Torvalds 贷款购买了一台 Intel 386 个人计算机，安装了 Minix 操作系统，并通过 Minix 操作系统附带的源代码，学习到了很多内核程序设计的理念。

由于 Andrew Tanenbaum 教授只愿意将 Minix 系统用于教学，不愿意强化系统功能，而 Linus Torvalds 是一个不服输充满探究精神的人，因此他萌生自己编写操作系统的想法。

而 GNU 计划产出的 Bash Shell 和 GCC 编译程序等自由软件，让 Linus 能够顺利的编写内核程序。最终，在 1991 年，他写出了能够在 Intel 386 计算机上运行的类Unix系统内核，并将其上传到网络上，提供免费下载。

当时 Linus Torvalds 是将该内核放在 Linux 目录下以供下载，所以该系统就从此被称为Linux 系统。

至此，具有划时代意义的Linux操作系统诞生了。

### 3. 操作系统内核和发行版

值得注意是，严格来说，1991年林纳斯·托瓦兹（Linus Torvalds）发布的Linux指的是操作系统的内核。

**内核是操作系统的核心部分：**

1. 向下层，内核提供硬件资源的管理。负责管理计算机的所有硬件资源，如CPU、内存和外部设备。
2. 向上层，内核独立于任何特定的用户界面和应用程序而存在，你可以把它看成是一个最底层的系统软件，为上层的应用提供基础服务。

了解操作系统内核后，我们还需要了解操作系统发行版的概念：

系统内核对于大多数用户而言，抽象层次都太低了，很难直接作为操作系统使用，缺乏很多必要的功能。比如：

1. 用户图形界面
2. 各种必要的应用程序(浏览器、文本编辑器、图像处理软件等)
3. 系统工具：用于系统设置和管理的工具，如网络配置、用户管理等。
4. ..

因此，在内核的基础上，结合这些用户层的软件和工具，我们才能得到一个完整的操作系统体验。**这就是操作系统的发行版。**

不同的发行版针对不同的用途和用户群体可能进行了特别的优化和配置，但基于同一内核的不同发行版在本质上是一致的。

关于内核和发行版它们的关系可以总结成：

1. 如果将内核比作汽车的引擎，那么发行版就相当于一辆包含引擎并配备有座椅、轮胎和车身等部分的完整汽车。
2. 没有内核，发行版就无法运行。而没有发行版，内核对大多数用户来说并不能真正提供操作系统的完整服务。二者互相依赖，共同构成用户实际使用的操作系统。

**因此，当我们谈论Linux时，我们可能指的是纯粹的Linux内核，也可能是基于该内核的完整操作系统发行版(通常指的是后者)。**

### 4. Linux的发行版本

1991年后，林纳斯发布Linux操作系统内核并开源后，涌现了大量的基于Linux内核的发行版。这里按照年份和特性总结一下：

1. **Slackware**：诞生于1993年。它是最古老的，且仍在维护的Linux发行版。
2. **Debian**：诞生于1993年，稍晚于Slackware。Debian以其社区驱动和稳定性著称。
3. **Red Hat Enterprise Linux (RHEL)**：诞生于1994年，由著名的Red Hat公司开发。

面向企业级市场，强调稳定性和安全性。RHEL提供付费支持，并且在企业环境中广受欢迎。

4. **Fedora**：诞生于2003年。作为RHEL的上游源，Fedora完全免费，主要由社区维护，并得到Red Hat公司的支持。Fedora的特点是注重创新和尝试新鲜技术。
5. **Ubuntu：**Ubuntu是公认提供最友好用户交互界面的Linux发行版本，诞生于2004年。Ubuntu适合桌面用户，特别是Linux新手。但它在云计算和服务器市场也有很强的存在感。
6. **CentOS：**基于RHEL构建，但完全免费，同样诞生于2004年。它提供与RHEL相似的稳定性和安全性，适合需要企业级稳定性但没有预算的中小型企业。CentOS在当下的生产环境中，是最普遍的服务器操作系统。

### 5. Linux成功的原因

Linux之所以成功归根结底有两个原因：

1. 开源免费。这是Linux成功最核心的原因，开源任何人都可以查看、修改和改进其源代码。
   - a. Linux采用单内核架构实现更加简单直接，容易理解和开发。使得Linux在发布开源之初，就获得了极大的支持。
   - b. 实际上世界上很多公司都为Linux内核源码添砖加瓦过，比如Intel、IBM、小红帽、微软、谷歌、华为等
2. 遵循POSIX标准，提高了Linux系统的兼容性。
3. 确实很强大。从稳定性、灵活性、性能乃至于兼容性多个角度出发，Linux都是一款非常优秀的操作系统。

在2000年左右的时候，服务器端操作系统的主流选择还是Windows。

但越来越多的公司开始无法忍受Windows Server的高额费用，随着Linux的发展成熟，Linux逐渐取代了Windows在服务器端的地位。

到如今，Linux已成为服务器端操作系统的霸主。

尤其在涉及云计算，Web服务器，大数据处理服务器等领域时我们可以默认它就是Linux操作系统的。

Linux系统的结构设计沿袭于Unix，它是一个层次分明的类似"坚果"的结构，如下图所示：

![](Linux_assets/卷一%20Linux基础/02_Linux发展历史/img003.png)

*图6-1Linux内核结构-图*

我们之前在讲虚拟内存空间，JVM虚拟机时，都提到了这种分层的软件设计架构，这里Linux系统结构的设计同样是一种分层的思想。

**分层的设计可以使得思考问题的复杂度降低，没有必要过度思考更深层次的问题。在计算机领域，有一句名言：没有解决不了的问题，如果有，那就加一层。**

Linux系统的层次结构，从内到外分别是"内核 --> 系统调用层 --> 库函数层 --> 应用层"。下面对这些层次进行逐一的讲解：

#### 6.1 内核与系统调用层

内核(Kernel)和系统调用这两层要合起来一起看：

1. 内核的作用是管理计算机的一切硬件资源，比如CPU、内存、外部设备等等。所以任何需要访问或控制硬件资源的操作，最终都需要与内核交互来实现。比如：
   - a. 文件系统管理
   - b. 外部设备管理（如键盘、显示器等）
   - c. 进程和线程资源管理
   - d. 内存管理(动态内存分配)
   - e. 网络通信
2. 但也不是所有的操作都需要和内核进行交互，当仅涉及数据在内存中的变化时，一般不需要内核参与：
   - a. 一般的函数调用
   - b. 加减乘除算术运算
   - c. 变量的声明、赋值等基本变量操作
   - d. 程序的流程控制

内核是不能让外界随意访问的，外界只能通过内核主动暴露给外界的接口去进行内核级别的操作，这就是**"系统调用"**。

"系统调用"为程序员编写应用程序，进行硬件层面的控制提供了可能。Linux操作系统的"系统调用"接口是以C语言风格暴露的。

**"系统调用"是用户应用程序和内核交互，控制硬件资源的一种常见手段，也是最直接和基本的手段。**

常见的系统调用有：文件操作，进程和线程控制，网络通信(一系列系统调用合集)等。

在后续的课程中，这些我们都会学习。

下面的例子可以帮助大家通俗的理解内核和系统调用的关系：

你可以把内核看成是银行的金库，储户的钱都是存在金库里的。但没有人可以直接去金库取钱，都需要通过银行柜员间接的从金库里取钱。

这个例子里，金库就是操作系统内核，它负责实现真正的功能，但外界不能直接交互内核。柜员就相当于系统调用，外界需要通过柜员间接地在金库里取钱。

#### 6.2 库函数层

在内核与系统调用层上面，是库函数层。

所谓库函数，可以将系统调用进行封装，使得程序员可以更方便、更简单乃至于更高效的使用系统调用。

关于系统调用和库函数的区别，如下：

1. 系统调用仅和操作系统内核有关，不同操作系统内核具有不同的系统调用接口。

2. 库函数是建立在系统调用之上的高级编程接口，它们封装了系统调用，提供了更方便实用的接口。不同的编程语言，一般具有不同的库函数实现，库函数是编程语言
的概念。

3. 库函数的功能和实现可以五花八门，但我们在学习一门编程语言时，更关注它的"标准库函数"。编程语言的标准库函数，为程序员提供了高效、可靠的方式来解决实现常见的编程任务。
4. 而且标准库函数还实现了跨平台性，在不同平台系统下，系统调用的接口是不同的，但不同平台系统的标准库函数至少在程序员使用起来是没有区别的。(用起来一样，但底层实现不同，这叫隐藏实现细节)

**库函数也提供了一种用户应用程序和内核交互的方式，但库函数不是一种全新的方式，而是对系统调用的封装。**封装的目的是为了实现跨平台的统一性，使用的方便性等。

###### 举例说明：库函数和系统调用的区别

在Linux操作系统下，进行IO操作有两个非常基础和重要的系统调用函数：

1. read函数
2. write函数
3. 这两个函数都是以C语言风格暴露的系统调用接口，它们的具体使用我们后续再讲。

在Windows操作系统下，也有类似的两个函数(Windows系统API，作用和Linux系统调用类似)：

1. ReadFile函数
2. WriteFile函数

标准库函数，以C语言为例子：

诸如：fwrite 、fread 、scanf 、printf 等涉及到数据输入输出的库函数，底层实现都是基于以上两种情况：

1. 如果在Linux下使用这些库函数，最终就是利用Linux系统调用的read和write函数
2. 如果在Windows下使用这些库函数，最终就是利用Windows系统API的ReadFile函数和WriteFile函数。

当然，不管在什么系统平台下，这些库函数的使用对于程序员而言都是一样的，而且使用简单，功能完善。这就是库函数的作用。

#### 6.3 应用层和shell

库函数层再往上就到了应用层，也就是一般的用户应用程序。用户应用程序在一定前提下可以直接进行系统调用和内核交互，也可以调用库函数，方便高效的实现一些功能。

应用层的程序中，shell是一个比较特殊的存在：

1. 首先shell是一个命令行解释器，它读取用户输入执行命令，shell解释这些命令并调用相应的程序来执行任务，执行完毕后又继续等待用户的下一次输入。
2. 具体到底层，shell可能调用库函数来实现功能，也可能直接进行系统调用来实现功能。

所以，**shell又提供了一种用户应用程序和内核交互的方式，它可能是系统调用的封装，也可能是库函数的封装。**

shell的版本有很多，在Linux下默认的shell程序是Bash ，它是GNU项目的产品之一，也是目前使用最广泛的shell，在随后的课程中我们都将使用Bash。（MacOS从19年开始选择Zsh 作为默认的shell程序。）

Bash作为一个应用程序，它的可执行程序的文件目录是：/bin/bash

#### 6.4 学习路线

搞清楚Linux系统的层次结构后，我们知道了三种和系统内核交互的方式：

1. 通过系统调用和内核直接交互，这是我们后续就要学习的内容——Linux系统编程。
2. 通过封装系统调用的库函数和内核间接交互，在C语言阶段我们已经学过很多这样的库函数了。比如printf、scanf、malloc等。
3. 通过封装系统调用或者库函数的shell和内核间接交互，这是接下来的几天需要学习的内容。

### 7. XShell的原理

要想搞清楚XShell的原理，我们先要了解一个网络协议：SSHSSH是一种远程连接通信的网络协议，基于SSH协议我们可以实现安全的远程登陆，从而访问和管理远程计算机。

SSH是一套基于C/S架构(客户端/服务端架构)的模型，即包含SSH服务端以及SSH客户端。客户端可以通过一定的方式进行远程连接服务端，而且一台服务端支持多台客户端连接。

## 03 常用shell命令

### 1. 概述

shell是用户和Linux系统交互的接口，也是程序员和系统内核交互的手段之一。

在本小节我们将学习一些基础的、常用的shell命令，以实现基本的功能。

作为程序员(而不是运维)，并不需要将所有的shell命令掌握，鉴于时间有限，建议大家先把该节列出的shell命令学会。

### 2. Shell命令的组成

Shell指令通常由几个基本的组成部分构成，这些部分共同定义了它们的行为和执行的方式。一个Shell命令的大体由以下几部分组成：

1. **命令**（Command）:
   - a. **这是Shell指令的核心部分，必不可少。**它指定要执行的操作，比如ls 、mv、cp 、mkdir 等。
   - b. 命令可以是shell进程本身内置的shell命令，也可以是外部程序。最常见的shell内置命令就是cd ，外部程序则多了(which命令就用于查找外部程序)。
   - c. **以C语言程序员的视角看，命令其实就是一个可执行程序的名字，它表示会实现某个功能。**
2. **选项**（Options）:
   - a. 选项通常以单个连字符- 开始（短选项），或者以两个连字符-- 开始（长选项，长选项大多可以省略为短选项）。
   - b. 选项不能单独存在，要和命令一起连用，用于改变命令的最终行为。
   - c. 例如，ls-l中的-l是一个选项，它告诉ls 命令以长格式列出目录内容。
   - d. **以C语言程序员的视角看，选项其实就是一个可执行程序启动时的特殊命令行参数，用于修改可执行程序的最终行为。**
3. **参数**（Arguments）:
   - a. 参数是传递给命令的额外数据。
   - b. 例如，在cpsource.txtdest.txt 命令中，source.txt 和dest.txt 是参数，它们指定了cp 命令的源文件和目标文件。
   - c. **以C语言程序员的视角看，参数其实就是一个可执行程序启动时所需要的参数，用于传递可执行程序执行时所需要的数据。**

对于大多数Shell指令而言，就仅有上述三部分组成，而一些shell命令可能还会多以下组成部分：

1. **重定向**（Redirection）:
   - a. 重定向用于改变命令的标准输入和输出。
   - b. 使用> 、<或>> 等符号可以将命令的输出发送到文件，或者从文件中获取输入。
   - c. 例如，ls>files.txt 会将ls 命令的输出保存到files.txt 文件中。
2. **管道**（Pipes）:
   - a. 管道符号| 用于将一个命令的输出直接作为另一个命令的输入。
   - b. 例如，catfile.txt|grep"searchstring" 会查找file.txt 中包含"search string"的所有行。

重定向和管道都是比较重要的指令组成部分，在本章节的后面我们将学习它们。

6. pwd - 打印工作目录。
7. type - 显示一个命令的类型（是内置命令、外部程序还是别名）。

###### shell命令中空格，双引号以及单引号的作用

在shell命令中，空格、双引号和单引号各自有着重要的作用：

1. **空格（或多个空格）**：
   - a. 空格在shell命令中通常用作参数或命令之间的分隔符。
   - b. 例如，在命令ls-l/etc中，空格分隔了命令ls 、选项-l和目录参数/etc 。
   - c. **如果参数中包含空格，则必须使用引号将整个参数括起来，否则shell会将其作为多个参数解释。**
   - d. **实际上，大多数shell命令背后就是一个C可执行程序，既然是这样，shell命令里的空格就类似于C可执行程序里输入多个命令行参数时的空格。**
2. **双引号** ( "..." )：
   - a. 双引号用于创建包含空格、制表符或换行等特殊字符的参数或**变量值**。
   - b. 当你想在参数中包含这些特殊字符时，可以使用双引号来确保shell命令正确理解它们。
   - c. 例子1：当你想在终端输出"hello world!"时，由于该字符串包含一个空格，所以需要用双引号或单引号括起来。这个指令可以写作：

   - i. `echo "hello world!"`
   - ii. 也可以是 `echo 'hello world!'`

   - d. 那么双引号和单引号有什么区别呢？一个比较常用的区别是：双引号可以用于识别shell的内置变量。

   - i. 指令 `cd -` 的执行需要依赖 Linux 的系统环境变量 `env` 当中的变量 `OLDPWD`。
   - ii. 你可以用 `echo "$OLDPWD"` 输出当前该变量的取值，但 `echo '$OLDPWD'` 会向终端输出字符串 `"$OLDPWD"`，因为单引号内的内容会被视为字面量字符串。

3. **单引号** ( '...' )：
   - a. 单引号的作用类似于双引号，它们也用于确保字符串中的空格被正确处理，不被shell分割。
   - b. 与双引号不同的是，单引号内的内容会被视为字面量字符串，shell不会进行任何变量替换或命令替换。
   - c. 例如，`echo '$VARIABLE'` 会原样输出字符串 `$VARIABLE`，而不是输出变量 `VARIABLE` 的值。

简单来说，空格用来分隔命令的不同部分，双引号用来防止分隔带有空格的字符串并允许输出变量的取值，单引号用来防止分隔带有空格的字符串并且引号内的内容都视为字符串处理。

### 4. 关机和重启命令

注意：**关闭主机之前，请务必先关闭虚拟机！**否则，可能会损坏虚拟机文件，导致不能启动虚拟机。

关机和重启命令，都需要管理员权限。所以：

### 5. 用户子系统命令

Linux操作系统是多用户的操作系统，而且具有以下特点：

1. 单个用户可以（同时）多次登录同一台Linux机器
2. 多个用户也可以（同时）登录同一个Linux系统，这与我们常用的Windows桌面版系统不太一样。

这是因为Linux系统多用于服务器系统，一台服务器显然不太可能仅供一个人使用。使用Linux系统就像是入住一间豪宅，豪宅有它的主人，家人和客人。

#### 5.1 Linux系统用户分类

类似地，Linux系统的用户大致也可以分为两类：

1. **特权用户，也叫超级用户或管理员用户。**
   - a. 特权用户的名字只有一个，固定为root。
   - b. 在系统中，root 用户的 UID（用户标识符）是 0
   - c. Linux 系统中只有一个 root 用户
   - d. root用户拥有系统的最高权限，可以使用系统的所有功能——包括删除其它用户这样的敏感操作。
2. **普通用户**
   - a. 普通用户是为日常工作和活动创建的用户账户。
   - b. 普通用户可以有很多个，它们只能使用系统的部分功能，名字可以多种多样。
   - c. 普通用户的权限受到限制，不能执行可能会影响系统稳定性和安全性的操作。

普通用户实际上可以进一步的细分为两类：

1. sudo用户，也称之为"sudoer"，即英文单词"superuser do"的缩写。
   - a. sudoer可以使用sudo命令来临时提高自己的权限**(假传圣旨)**，从而可以执行一些（而不是所有的）特权命令。
   - b. 比如一个普通用户，若想要使用aptinstall 命令在系统上安装软件或者使用shutdown命令关机，都需要加上sudo开头等等。
2. 非sudo用户。不具备使用"sudo"临时提升权限的能力。

普通用户的shell命令提示符是$，root的shell命令提示符是#，如下图所示：

关于普通用户当中的sudoer用户，可以查看下面的补充内容：

###### 如何查询和创建一个sudoer用户？

我们把可以用sudo 提升权限的普通用户称之为sudoer ，你可以通过指令查看当前系统中的sudoer用户：

```c
grep sudo /etc/group #查询sudo组的用户，该组用户就是sudoer
```

该指令的作用是：在"/etc/group"文本文件中搜索包含"sudo"这个字符串的行。

"/etc/group"文本文件是一个Linux系统配置文件，包含了该Linux系统上的用户组信息。

我们在安装Ubuntu时创建的初始用户就是一个拥有sudo 权限的普通用户，就是一个sudoer 。

当然并不是所有的普通用户都是sudoer ，如果你希望将某个用户添加为sudoer，可以使用指令：

```c
sudo adduser test sudo #将test用户添加为sudoer
sudo whoami #显示当前正在执行该命令的用户的用户名，如果当前用户是sudoer，会输出root
sudo deluser test sudo #将test用户移除sudo组
```

#### 5.2 激活root用户

Ubuntu刚安装时，默认是不激活root用户的，创建的第一个用户只是一个具有sudo权限的普通用户。

若想激活root用户，需要使用以下指令，给root用户设置密码：

```c
sudo passwd root
```

注意输入密码时和Windows不一样，它不会显示键入了多少字符。但你不用担心，只管输入后回车即可。

若激活了root用户，也请你把密码记录一下避免忘记密码。

#### 5.3 查看所有用户

Linux系统下的所有用户，在 passwd 配置文件中都有一条相关记录。我们可以通过下列指令打开这个配置文件：

```c
sudo cat /etc/passwd #cat指令用于将文件打印出来
```

比如我们可以找到我们创建的用户的信息：

wgd:x:1000:1000:WGD:/home/wgd:/bin/bash每一行对应一条记录，每条记录有多个字段，字段之间以 : 分割。我们可以在5号手册中查看 passwd 文件的格式和规范：

```c
$ man 5 passwd
```

以下内容复制粘贴自man手册：

**"/etc/passwd"文件**中每个用户账户包含一行，包含使用冒号 (“:”) 分隔的七个字段，分别是：

1. 登录名
2. 登录密码(现已被x代替，避免明文存储密码导致安全问题)
3. 用户UID
4. 用户组GID
5. 用户名以及可能存在的用于解释用户名的注释字段
6. 用户的家目录
7. 用户登录的shell程序版本

wgd用户的家目录是：/home/wgd ，注意/home 本身不是家目录。

wgd用户使用的shell版本是：bin/bash ，这里就是一个可执行程序的路径名。

为了安全考虑，Ubuntu会把密码加密后存储在/etc/shadow 文件中，你可以用下列指令查看这些加密密码：

```c
sudo cat /etc/shadow
```

你可能还发现一个细节：查看passwd 文件，出现了很多不认识不了解的用户，那些是什么用户呢？

其实这些用户都属于**系统用户**，也称为伪用户，这些用户的存在，为不同的系统服务和进程提供了不同的身份和权限，是Linux系统的一种安全机制，当然它们都不能用于登录操作。

#### 5.4 useradd添加用户

我们可以使用 useradd 命令来添加用户，格式如下：

```c
格式:
    useradd [选项] username
常用选项：
    -m, --create-home
       #如果不添加该选项，则不会自动创建家目录文件夹
       #添加上该选项，则会在创建用户时自动创建家目录文件夹
    -s, --shell SHELL程序路径
       #如果不添加该选项，新建用户的默认为/bin/sh
       #添加上该选项,则可以指定用户登录的shell程序,比如/bin/bash
```

比如我们可以这样用：

```c
sudo useradd test1 #创建用户test1，但不会创建它的家目录文件夹，使用的shell默认为sh
sudo useradd -m test2 #创建用户test2，会创建它的家目录文件夹，使用的shell默认为sh
sudo useradd -m -s /bin/bash test3 #创建用户test3,会创建它的家目录文件夹,并且指定登录shell是/bin/bash
```

注意:

-s/bin/bash 必须放在一起，但它和-m 的顺序是无所谓的。

细节：

执行这些命令用于创建一个新用户，我们会发现一个现象：指令执行完毕后，没有任何反馈信息，没有创建用户成功这样的提示。

这里就涉及到Linux的设计哲学了：

**指令执行，没有反馈没有消息，就是最好的反馈最好的消息。**

所以当你输入一条指令执行，没有给出任何反馈，那就说明执行成功了。相反，如果给出反馈信息，那你就需要注意了，因为：

1. 这有可能是指令执行失败了，反馈是错误信息。
2. 也有可能是给出的一些重要的提示。

总之Linux的这种设计旨在简化命令行的输出，只在必要时才提醒用户，从而提升效率和清晰度。

#### 5.5 userdel删除用户

我们可以使用 userdel 命令来删除用户，格式如下：


我们可以使用 passwd 命令来给用户设置密码，普通用户通常只更改其自己账户的密码，而超级用户和sudo可以更改任何账户的密码。

#### 5.7 su切换用户

我们可以使用 su(switch user) 命令切换到另一个用户，格式如下：

```c

    su [选项] [username]

```

比如我们可以这样用：

#### 5.8 exit退出当前用户

"exit 命令"可以用来退出当前登录用户，转而切换到上一次登录的用户。

```c
exit #退出当前登录用户
```

从实际上来说，当你使用su 命令切换到另一个用户时，实际上是在当前终端会话中启动了一个新的 shell 进程，该进程以目标用户的身份运行。

当你使用exit 命令退出当前登录用户时，实际上就是结束了当前 shell 进程，并将控制权还给之前的 shell 进程。

整个su 和exit 的过程比较复杂，牵扯到操作系统进程的管理，但我们可以粗略、通俗的将这个过程理解成栈模型的应用：

1. 执行su 命令，这个过程可以看成是新用户会话进栈的过程，栈顶用户会话就是当前登录用户
2. 执行exit 命令，这个过程可以看成栈顶用户会话出栈的过程，那么前一个登录的用户就会成为新的当前登录用户。

可以用下图来理解：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img004.png)

*图5.8-1切换用户栈-图*

既然使用一个这样的栈结构来维护用户登录，那么当某个用户存在栈结构中时，该用户是无法被删除的。

### 6. Linux文件管理系统（重点）

在Linux系统中，程序员最常使用的命令肯定是和文件管理系统相关的指令，即"文件子系统命令"。但在具体讲解，学习这些指令之前，我们需要对Linux文件系统有一个基本的了解。

#### 6.1 Linux文件管理系统的特点

Linux的文件管理系统和Windows有很大的区别：

1. Linux是以树形结构来管理文件系统的，树的根结点就是根目录，用/ 表示。但Windows操作系统中，每一个盘符都可以视为一棵树，所以 Windows 下的文件系统是一种"森林"模式。
2. Linux是以分门别类的方式来管理文件的，也就是说，我们会将功能相似的文件放到同一个目录下进行管理。但Windows操作系统中，更习惯于将同一套内容直接集中放在一起，而不是按功能分类存放。
   - a. 比如在Linux安装QQ，那么可执行程序文件、配置文件、用户数据等可能放在不同的目录下。
   - b. 而在Windows当中安装QQ，往往就是QQ 文件夹，所有相关内容都放在一起。

###### Linux常见目录的功能

为了屏蔽这些硬件层面带来的差异性，简化用户学习成本，提高用户使用体验，我们就在物理文件系统上加一层：**虚拟文件管理系统**

#### 6.3 硬链接和硬链接数

类比虚拟内存空间和物理内存地址的映射，虚拟文件系统（VFS）中的文件和物理文件系统中存储的数据也存在映射的关系。

基于这样的一种映射关系，完全可能出现多个VFS中的文件，映射到硬盘上的同一块区域。如下图所示：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img007.png)

*图6.3-1硬链接-图示*

这种"多对一"的映射关系，就是硬链接：

**硬链接允许VFS当中的多个文件可以映射到物理文件系统的同一文件中，也就是说，尽管在VFS中，这些文件或目录看起来可能位于不同的位置，或者有不同的名字，但它们实际上都代表同一份数据和信息。**

那么什么是硬链接数呢？

硬链接数指的是一个文件拥有的硬链接数量，类似于"有多个指针指向了同一片内存空间"，于是"指针的总数量"就被称之为"硬链接数"，即VFS中有几个文件指向同一份数据。

比如上图的"文件A"，VFS中的file1和file2文件都指向它，它的硬链接数就是2个。同时file1 和file2 的硬链接数也是2个。

为什么？

原本的硬链接数是2，原因如下图所示：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img009.png)

*图6.3-3硬链接-图示3*

所以我们实际上可以得出一个结论：Linux的文件系统实际上就是依靠文件、目录以及硬链接等概念组合起来的。

补充：

硬链接数的设计，是一种"引用计数法"，它是内存管理当中非常重要的一种算法策略。

在文件系统中，进行文件的删除，实际上执行的操作就是将"硬链接数--"当硬链接数减少到0时，文件系统会认为该区域不再被任何文件/目录引用，此时它才会释放该区域内存空间。

#### 6.4 inode的概念

inode是词组indexnode 的缩写，即"索引结点"。

inode是物理文件系统中的概念，你可以将它视为物理文件系统中文件的"入口或起始位置"。它是物理文件系统中某个文件的唯一性标识，索引。

VFS中的文件通过硬链接链接到物理文件系统中的文件，就是通过链接到inode完成的。

我们可以用下图来描绘inode 这个概念：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img011.png)

*图6.4-1inode-图示*

inode除了视为文件的入口，还会存储该文件的元数据信息，比如：权限、所有者、大小、时间戳等。

所以：

1. 硬链接实际上是VFS中的文件对物理文件系统中特定inode的引用。
2. 硬链接数实际上是链接到某个inode上文件的个数。
3. 当链接到inode上的文件数量等于0时，文件的数据才会真正被释放。

#### 7.2 cd改变当前工作目录

cd 命令是一个非常常用的shell命令，它的作用是改变当前工作目录。cd是 "Change Directory" 的缩写。

该指令的格式如下：

```c
$ man cd
    cd — change the working directory
    #切换当前工作目录
格式：
    cd [选项] [directory]
    #该命令没有什么常用的选项。
    #directory也是可选的，如果不输入，则回到家目录
```

该指令有以下常用方式：

```c
$ cd # 什么都不输入，切换到用户家目录
$ cd /usr/lib # 切换到/usr/lib目录
$ cd / # 切换到 / 目录

$ cd .. # 切换到父目录，上级目录

```

cd-这个命令并不常用，但需要注意的是它并不是栈结构管理目录跳转的，而仅是用环境变量中的OLDPWD 属性来保存上一次目录。

#### 7.3 mkdir创建新目录

mkdir 命令用于创建目录（文件夹），它的英文全称是 "make directory"。

该指令的格式如下：

```c
$ man mkdir
    mkdir - make directories
    #复数形式，表示它可以创建多级目录
格式:
    mkdir [选项] directory...
    #...表示可以写多个目录，表示创建多个新目录
常用选项：
    -p, --parents
    #如果父目录不存在，则创建父目录
    #该选项添加后，可以用于创建多级目录
```

常用方式：

```c
$ mkdir dir #在当前工作目录下创建一个新文件夹dir
$ mkdir dir1 dir2 dir3 #在当前工作目录下创建一个新文件夹dir1、dir2以及dir3
$ mkdir -p a/b/c #允许创建多级目录a/b/c，即便上级目录不存在
```

注意：

1. mkdir 只能用于创建目录，它不会创建文件。
2. 不要用后缀名来区分文件和文件夹(目录)：
   - a. 有后缀名的也可以是目录名。比如一个目录叫"a.txt"，这虽然不太正常，但完全可以。
   - b. 没有后缀名的也可以是一个文件名。比如一个文件叫"a"，在Linux系统中，可执行文件都是没有后缀名的。
3. 在创建多级目录时，如果父目录不存在，则必须加上选项-p ，否则会创建失败！

#### 7.4 rmdir删除空目录

rmdir 命令用于删除空目录（文件夹），它的英文全称是 "remove directory"。

**注意：rmdir命令只能用于删除空目录！！！**

该指令的格式如下：

```c
$ man rmdir
    rmdir - remove empty directories
    #复数形式，表示它可以删除多级空目录
格式：
    rmdir [选项] dirctory...
    #...表示可以写多个目录，表示删除多个空目录
常用选项：
    -p, --parents
    #表示递归的删除空目录和空的父目录
```

常用方式：

```c
$ rmdir dir #删除空目录dir
$ rmdir dir1 dir2 dir3 #删除空目录dir1、dir2以及dir3
$ rmdir -p a/b/c #递归的删除目录a/b/c
```

对于指令rmdir-pa/b/c ，带上-p 选项后，指令的作用是：

1. 它会先检查a/b/c 目录，若目录为空，则删除该目录。
2. 然后递归检查a/b 目录，若目录为空，则删除该目录。
3. 最后递归检查a 目录，若目录为空，则删除该目录。
4. 在这个过程中，发现任一目录非空，则删除停止。

#### 7.5 通配符

Linux系统的通配符（wildcard character）是一种用于模式匹配的特殊字符，常用于指令中的文件名匹配和搜索操作。通配符允许你指定一个模式，然后搜索符合该模式的文件名或其他字符串。

通配符非常强大好用，希望大家熟练掌握它。

比较常用的通配符(模式)有：

1. * ：表示匹配0个或者多个任意字符
2. ? ：表示匹配1个任意字符
3. [...] ：根据中括号内的字符进行匹配。
   - a. [characters] 表示匹配中括号内的任意**一个**字符。
   - b. [!characters] 表示匹配中括号外的任意**一个**字符。

我们可以在某个目录下使用指令：

```c
mkdir dir dir1 dir2 dir3 dira dirb dirc diraaa dirbbb dirccc a b c dirx diry dirz
```

执行以下指令：

```c
rmdir dir[abc]
```

效果是什么？会删除目录：dira dirb dirc执行以下指令：

```c
rmdir dir[!abc]
```

效果是什么？会删除目录：dir1 dir2 dir3 dirx diry dirz。但不会删除dir目录，因为要匹配1个字符再次执行以下指令：

```c
rmdir dir*
```

效果是什么？会删除目录：dir diraaa dirbbb dirccc，此时可以匹配0个字符。

最后执行指令：

```c
rmdir *
```

下面逐一解释这些内容：

1. 总用量大体上描述当前目录下所有文件和子目录占用的磁盘空间的总和（磁盘块的数量），数字越大占用空间越大，但这个数值往往不是真实磁盘空间占用。
2. 第一列数据，即第一列的字符，诸如l 、d 、- 等。它们的含义是：
   - a. - 表示它就是一个普通文件。
   - b. d 表示它是一个目录文件夹。d实际上是directory的缩写。
   - c. l 表示它是一个符号链接（也叫软链接），即指向另一个文件的引用。通俗的说，它就是Windows操作系统的快捷方式。字符l 是词组"symbolic link"的缩写。
   - d. c 表示一个字符设备文件。需要注意的是，Linux的设计哲学中一切皆文件，会把那些计算机的物理设备也当成文件进行处理。所谓字符设备文件，就是**逐字符数据传输处理**的硬件设备。典型的有：鼠标、键盘、显示器等。c实际上是单词character的缩写。

   - f. s 表示本地套接字。它主要用于进程间通信，这个我们后面系统编程会讲到。s是单词socket的缩写。
   - g. p 表示有名管道（也叫具名管道），它也主要用于进程间通信。p是词组named pipe的缩写。
3. 从第二列开始，到第十列，一共九列数据，也就是9个字符，把它们分为三组：
   - a. 前三列：表示拥有者的读、写、执行的权限。若有权限则分别用r、w、x表示，若没有权限则用- 表示。
   - b. 中间三列：表示拥有者组的读、写、执行的权限。若有权限则分别用r、w、x表示，若没有权限则用- 表示。
   - c. 后三列：表示既不是拥有者也不是拥有组的其它用户的读、写、执行的权限。若有权限则分别用r、w、x表示，若没有权限则用- 表示。
   - d. r是单词"read"的缩写，w是单词"write"的缩写。可能有些同学对可执行权限表示的字母x 存在疑惑，x其实不是任何单词的首字母缩写，它取自单词"execute"的第二个字母"x"。之所以不取首字母e ，是因为e在很多地方都被占用了。

紧接着上面一堆wxr- 这些权限的标记后，会存在一个数字：1、2等。这个数字是什么意思呢？

这个数字的意思是该文件/目录的**硬链接数**，关于硬链接数的概念上面已经讲解过了。

这里不再赘述。

再往后面，ls-l 指令输出的内容就比较简单了：

1. 第一个wgd 表示此文件的拥有者用户名
2. 第二个wgd 表示此文件的拥有组的组名
3. 第三个数字表示文件的大小，默认以字节为单位。如果你希望用更大、更好理解的单位表示大小，**则可以添加上"-h"选项，即使用命令"ls - lh"。**如果你还希望展示隐藏文件，可以使用命令"ls -alh"。
4. 再往后就是文件的最后修改时间，注意不是创建时间。
5. 最后是文件的名字。

#### 7.8 cp复制文件或目录

**cp(copy)命令用于复制文件或目录。**它是一个非常常用的命令，可以将文件目录复制到另一个位置，类似于Windows操作系统中的"复制 - 粘贴"操作。

该命令的使用格式如下：

```c
$ man cp
    cp - copy files and directories
    #可以同时复制多个文件/目录
格式：
    cp [选项] SOURCE DEST
    #将一个目录复制到另一个目录下或者将源文件复制到目的文件中，这里DEST可以是文件也可以是目录
    cp [选项] SOURCE... DEST
    #将多个文件或者目录复制到目标目录下，此时DEST只能是目录
常用选项：
    -n, --no-clobber
       #若在复制的过程中发现文件已存在，则不会覆盖。不添加该选项，默认会覆盖已存在文件
    -i, --interactive
#若在复制的过程中发现文件已存在，则会询问用户是否覆盖，选择权力交给用户。
```

#输入y/Y表示覆盖，其它任意字符表示不覆盖

-R, -r, --recursive

#当SOURCE是一个目录时，添加该选项，用于递归复制目录下所有的内容，即包括所有子目录和文件。

#复制目录时，应该总是添加上该选项常用方式举例：

```c
$ cp text1 text2 # 将text1复制到text2中；如果text2存在，则覆盖。
```

```c
$ cp text1 text2 dir # 将text1,text2复制到目录dir中；如果文件已存在，则覆盖。
```

```c
$ cp -n text1 text2 # 将text1复制到text2中；如果text2存在，不覆盖。
```

```c
$ cp -i text1 text2 text3 dir # 将text1,text2,text3复制到目录dir中；如果文件已存在，则提示用户是否覆盖。
```

```c
$ cp -r dir1 dir2 # 递归地将目录dir1复制到目录dir2
```

特别需要注意的是：

1. 使用cp命令复制创建新文件时，实际上是在创建一个内容相同但是具有不同inode编号的新文件：
   - a. 尽管新旧文件的内容相同，但它们在文件系统中被视为两个独立的实体
   - b. 并且各自拥有不同的物理存储空间和inode编号。
2. 使用cp命令覆盖目标文件时，会直接覆盖目标文件的内容，目标文件的inode并不会发生改变。这个过程一般不会修改文件的元数据(但最后修改时间、大小等这些内容会发生变化)，而是修改了文件的内容。
3. 当复制的源是一个目录文件夹时，必须要加上-r 选项，否则指令会直接执行失败报错。


常用选项：

### 8. 指令起别名

在C语言中，我们学习过typedef 关键字给类型起别名，在Linux操作系统中，命令也是可以起别名的。

有些shell命令明显比较长，自然我们就想给这些命令起一个简短的别名，方便以后使用，alias命令就是用来做这个事情的，这个单词翻译过来就是别名、外号的意思。

其基本的使用格式如下：


有一个别名大家需要记住：ll ，它实际上是ls-alF 指令的别名，它是Linux系统默认存在的指令别名。这个ll 的别名提供了一个快速的方式来显示当前目录下的所有文件和目录的详细列表，包括隐藏文件（以. 开始的文件）。

### 9. 改变文件权限指令

关于文件的权限，我们在前面ls-l 命令中已经讲解过了。某个用户对一个文件(目录)具有三种权限：

1. 可读，用r表示，不可读用-表示
2. 可写，用w表示，不可写用-表示
3. 可执行，用x表示，不可执行用-表示

那么如何对一个文件的权限进行修改呢？我们可以使用shell命令—— chmod 指令。它是词组"change mode"的缩写，允许用户设置或更改文件或目录的权限。

为了更加清晰的讲解清楚这个指令，我们还需要了解一些目录以及权限相关的基本原理知识。

#### 9.1 目录究竟是个什么东西？

对于普通的计算机用户而言，他们会觉得目录(文件夹)和文件是完全不同的两个概念。

在上面讲解指令时，我们也依照大家以往的习惯，将指令的作用根据目录和文件做了区分，但实际上在Linux系统下**目录也是文件的一种，或者说目录是一种特殊的文件**。

比如：ls-l 展示的信息中d 就表示该文件是一个目录文件。

既然目录是一个特殊文件，那么目录文件中存储的是什么数据呢？**（注意：这里指的是物理文件系统中的目录文件实际存储的内容）**

**目录文件中存储的是当前目录下其他文件和子目录的信息，这些信息被称之为目录项（directory entries）。**

**目录项中主要存储这个目录/文件的文件名以及inode编号，目录项不会直接存储文件内容数据！！**

**而诸如：文件类型、权限、硬链接数、文件大小、时间戳等文件元数据信息则存储在inode中。**

**在逻辑上，目录文件中的目录项是以链表的形式(某些文件系统还可能采用B树或哈希表等结构)链接起来的。**

比如一个dir1目录，树形图如下所示：

*图9.1-1目录原理讲解-图1*

#### 9.2 目录权限

既然目录是一个特殊文件，存储的是目录项数据，那么目录权限对目录操作的影响就很直观了：

1. **读权限（r）:**
   - a. 对于目录，读权限允许用户列出该目录内的文件和子目录名。
   - b. **目录的读权限，就是读目录文件中目录项数据的权限，如果没有该权限，自然就不能展示当前目录信息了。**
   - c. 目录的读权限影响ls 这样罗列目录信息的指令。
2. **写权限（w）:**
   - a. 对于目录，拥有写权限允许用户在该目录内**新增、删除或重命名**文件和子目录。
   - b. **目录的写权限，就是修改目录文件中目录项数据的权限，如果没有该权限，就无法修改、删除这些数据项了。具体表现出来就是：无法创建新目录，无法删除旧目录、不能重命名等。**
   - c. 思考一下：这种情况下当前目录下的文件，内容能不能修改呢？当然可以，目录项中不存储文件内容！
   - d. 目录的写权限影响的命令很多，如：mkdir、cp、mv、rm等
3. **执行权限（x）:**
   - a. 什么是目录的执行权限呢？通俗的说，拥有目录的执行权限就是可以进入该目录。所以目录的执行权限会影响cd 命令。

目录的执行权限是目录最基本的权限。没有执行权限的目录是“不可进入、不可找到”的目录，那么目录将不可读也不可写。

   - c. 目录的读写权限都依赖执行权限，没有执行权限，目录即便有读写权限也没有意义。

#### 9.3 普通文件权限

理解了目录权限，我们再来一起看一看普通文件的权限，对文件操作的影响：

1. **读权限（r）:**
   - a. 对于普通文件而言，读权限允许用户查看文件的内容。
   - b. 思考一下：读某个目录下的文件，需要该目录的读权限吗？
   - c. 当然不需要，文件内容并不是存储在目录项中的，查看文件内容仅需要目录有执行权限就可以了。
2. **写权限（w）:**
   - a. 对于普通文件而言，写权限允许用户修改文件的内容。
   - b. **需要注意的是：文件的删除、重命名等权限在于目录的写权限，而不在于文件本身。**
   - c. 思考一下：如果一个文件是只读的(即没有写权限)，能不能删除它？当然可以，前提是目录具有写和执行权限。
   - d. 当然文件的写权限只是文件系统级别的权限限制，在操作系统层面仍然有很多种方式可以绕过这种权限，强行修改一个只读文件。比如利用vim 指令就可以强行修改一个只读文件，再比如root(sudo)超级用户权限，也可以完全无视这种限制。
3. **执行权限（x）:**
   - a. 执行权限允许用户运行文件作为一个程序或脚本。
   - b. 如果你没有对文件的执行权限，即使文件是一个正确的可执行程序或脚本，你也无法直接运行它。

#### 9.4 chmod指令

chmod指令用于修改文件的权限，它有两种比较常用的方式：

##### 9.4.1 文字设定法

利用**文字设定法**直观的设定一个文件的权限，这种方式在指令执行时是比较常用的，因为它很直观好理解。但是到了Linux系统编程时，写代码改变文件权限的时候，这种方式就不是很常用了。

其基本格式如下：

```c
chmod 用户类别[+=-][rwx] file
```

其中用户类别有四种：

1. u：表示改变文件拥有者对文件的权限
2. g：表示改变文件拥有者组对文件的权限
3. o：表示改变其它用户对文件的权限
4. a：表示改变所有用户对文件的权限

+-= 分别表示：

1. +：给目标用户添加指定权限
2. -：给目标用户删除指定权限
3. =：给目标用户直接指定权限

rwx 则很简单，分别表示可读、可写、可执行三种权限。

使用举例：

```c
$ chmod o+w text1 #表示将文件text1的其他用户（Others）的写权限设置为开启
$ chmod a-r dir1/ #表示将目录dir1/的所有用户的读权限（Read）设置为关闭。
```

```c
$ chmod u=rwx,g=rx,o=r text1
```

最后一条指令的意思是：

1. u=rwx ：表示将文件text1 的所有者用户的权限设置为可读、可写、可执行。
2. g=rx ：表示将文件text1 的所属组的权限设置为可读和可执行，但不可写。
3. o=r ：表示将文件text1 的其他用户的权限设置为只读，不可写，不可执行。

##### 9.4.2 数字设定法

什么是权限的数字设定法呢？我们观察一下某个文件的权限：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img024.png)

*图9.4.2-1数字设定法-图1*

一共有9个字符，于是我们用1表示对应位置有权限，0表示没有权限，上述dir目录的权限就可以用二进制表示成：111111101这就是一种数字设定法，用于设置权限。但二进制数毕竟有点长，于是我们把它转换成八进制：775

所谓权限的设定法，就是用这样的八进制数来表示一个权限。这种表示方式显然不如文字表示法直观易理解，但它在编码过程中使用会更方便，是程序员日常表示权限更常用的方式。

以下是一些常见的数字权限：

1. 775 ：775意味着拥有者和拥有组用户权限全开，其它用户则没有写权限。一般新建的目录或可执行文件就拥有这个权限。
2. 664 ：664意味着拥有者和拥有组都可读可写，其它用户则只读。一般新建的文件就拥有这个权限。
3. 700 ：除了拥有者外其它用户没有权限，可用于私人文件。
4. 777 ：所有用户的所有权限都打开，一般不会这么做。
5. 666 ：所有用户读写权限打开，一般也不要这么做。

这些权限数字都不用记，因为用多了见多了自然就记住了，就算记不住现场推也不会花很多时间。

这里我们，仅希望大家记住一个重要结论：

**数字表示法表示权限时，三个整数中的某个数字如果是奇数，那么对应用户一定具有执行权限。反之若是偶数，则一定没有执行权限。**

比如：

1. 看到775 这样的权限数字，也许你不能反应过来所有的权限，但你应该立刻想到：

所有用户都有执行权限

2. 看到664 这样的权限数字，你应该立刻想到：所有用户都没有执行权限
3. 看到766 这样的权限数字，你应该立刻想到：只有拥有者具有执行权限，其它用户都没有。

思考一下为什么？

**因为：在二进制表示中，一个整数是奇数的条件是它的二进制表示的最低有效位必须为1。（&运算判断奇偶性还记得吗？）**

可执行权限是所有权限当中最重要的，把它放在三种权限的末尾，它就具有了上述结论性质，非常nice~使用举例：

```c
$ chmod 664 text1
```

作用是将text1文件的权限设置为：rw-rw-r--

#### 9.5 补充：文件权限掩码

在类Unix操作系统中，**文件权限掩码（umask，user file creation mode mask）**是一个用于设置新文件和新目录默认权限的系统设置。

当你在Linux系统中创建一个新文件或目录时，Linux会根据特定的默认权限来赋予新文件/目录的权限：

1. 对于文件而言，默认权限通常是666（可读可写无执行权限）
2. 对于目录而言，默认权限通常是777（可读可写可执行，权限全开）

**文件权限掩码umask的值，则决定了从默认权限中"掩去"（即清除）哪些权限。**

想要计算新文件、目录的实际权限，需要先将umask按位取反，然后再与默认权限做按位与运算得到。

举例：

Ubuntu默认的umask一般是0002(八进制)，即需要移除其它用户的写权限。

实际权限计算过程如下：

1. **对新创建的文件：**
   - a. 默认权限：666 -> 110110110 （rw-rw-rw-）
   - b. umask：0002 -> 000000010
   - c. ~umask：111111101
   - d. 实际权限：110110100 -> 664 （rw-rw-r--），这意味着所有者和所属组有读写权限，而其他用户只有读权限。
2. **对新创建的目录：**
   - a. 默认权限：777 -> 111111111 （rwxrwxrwx）
   - b. umask：0002 -> 000000010
   - c. ~umask：111111101
   - d. 实际权限：111111101 -> 775 （rwxrwxr-x），这意味着所有者和所属组有完全的读写执行权限，而其他用户有读和执行权限。

通过合理设置umask ，系统管理员可以控制新文件和目录的访问级别，防止未经授权的用户访问敏感信息。这种方式确保了系统中新创建的文件和目录不会意外地获得过高的权限，从而增强了系统的安全性。

#### 9.6 补充：Linux 文件模式（mode）位结构解析

在 Linux 底层实现中，会使用一个mode_t类型的mode 变量来存储文件的状态信息。

mode_t本质上是一个类型别名，在 64 位 Ubuntu 系统中通常为unsignedint ，即**4 字节无符号整型**。

**不过需要注意的是，这个整型变量虽然一共有32位，但真正有意义的只有低16位。**

这个mode变量并不是单纯用来保存“权限数字”的。

它内部同时编码了三类信息

1. 文件类型
2. **特殊权限位（setuid / setgid / sticky）**
3. 普通 rwx 权限位

我们平时在命令行中看到的“775”、“664”，实际上只是mode变量低位权限部分的一种八进制表达方式。

mode在后续文件系统编程中非常常见，例如：

1. stat()返回结构体中的st_mode 成员
2. chmod()的第二个参数，用于表示改变后的文件权限
3. open()的第三个参数（创建文件时），表示新创建文件的权限

因此有必要对它的位结构做一个基本了解。

本节内容权当扩展认知，并不作为重点掌握内容。

虽然mode_t是 32 位，但其有效布局遵循经典 Unix 16 位设计：

2. 再往上 3 位是特殊权限
3. 最高 4 位是文件类型

如果仅表示权限的话，带上普通权限和特殊权限，需要使用一个**四位八进制数**。

如果再带上文件类型的话，就需要使用一个**六位八进制数**。

举几个例子。

##### 9.6.1 最常见的mode写法：仅表示普通权限

这种写法只包含**低 9 位 rwx 权限**，对应三组用户的普通权限：

用户 / 组 / 其他例如：

775664755600含义分别为：

| 八进制 | 含义 |
|---|---|
| 775 | rwxrwxr-x |
| 664 | rw-rw-r-- |
| 755 | rwxr-xr-x |
| 600 | rw------- |

这种写法是最常见的。

在 Shell 指令中，我们可以直接这样写：

chmod 775 file**这是因为 chmod 命令默认把数字参数按八进制解释，所以不需要在前面额外加 0。**

而如果在函数中，在写代码时，需要指定文件的mode，情况就不一样了。

C语言默认将数字当成十进制处理，所以需要带上八进制的前导“0”，明确标志这是一个八进制数。

上面的写法就要变成：

这个小细节需要注意下。

##### 9.6.2 mode表示全部权限

如果需要包含特殊权限（setuid / setgid / sticky），则需要写成**四位八进制数**：

特殊权限位 + 用户权限位 + 组权限位 + 其他人权限位例如：

1. 4555，开启setuid权限，表示文件执行时使用拥有者权限，普通权限为555。
2. 2775，开启setgid权限，表示文件执行时使用拥有者组权限或目录下的文件自动继承目录的所属组身份，普通权限为775。
3. 1664，开启sticky权限，表示此目录下仅文件拥有者可删除文件，普通权限是664。
4. 6775，同时开启setuid和setgid 权限。
5. 7777，特殊权限全开，普通权限也全开。

和上面一样，如果在chmod指令中使用文件mode，可以直接使用这个4位数字。

而如果在C语言代码中使用，则需要加上八进制的前导标志“0”：

045550277501775...

无论是 shell 的chmod指令，还是 C 语言中的chmod() / fchmod() / fchmodat()等相关系统调用函数，都可以修改文件的：

1. 普通权限
2. 特殊权限

当然前提是你拥有修改的资格，比如你是文件的拥有者，或者你是root管理员。

##### 9.6.3 mode表示文件类型 + 所有权限

**如果再加上文件类型，就需要写成六位八进制数。**

结构为：

文件类型(高2位八进制) + 特殊位(1位八进制) + 普通权限(3位八进制)常见文件类型八进制表示有：

| 类型 | 八进制表示 |
|---|---|
| 普通文件 | 0100000 |
| 目录 | 0040000 |
| 符号链接（软连接） | 0120000 |

举例：

100755其中：

1. 最高位的两位八进制数，10，表示普通文件。
2. 中间的“0”表示未开启特殊权限。
3. 普通权限是755

再比如：

041775表示：

1. 最高位的两位八进制数，04，表示目录文件。
2. 中间的“1”表示开启“目录下文件继承目录所属组身份”，即开启sticky权限。
3. 普通权限是775

**但是需要特别强调的是：**

虽然mode字段内部确实包含文件类型位，但文件类型属于文件的固有属性，它在文件创建时就已经确定。

文件类型不是可以通过shell指令chmod或函数chmod()随意修改的属性。

换句话说：

1. chmod只能修改**特殊权限位 + 普通权限位**
2. 文件类型位不会被修改
3. 内核会忽略或拒绝试图改变文件类型的操作

##### 9.6.4 总结

总结 mode 数字：

1. 三位八进制 → 普通权限
2. 四位八进制 → 特殊权限 + 普通权限
3. 六位或七位八进制 → 文件类型 + 特殊权限 + 普通权限
4. 文件类型虽编码在mode中，但不可通过chmod修改

**三种特殊权限在 ls 中的位置总结**

| 权限类型 | 显示位置 | 小写（表示有执行权限） | 大写（表示没有执行权限） |
|---|---|---|---|
| setuid | 用户执行位 | s | S |
| setgid | 组执行位 | s | S |
| sticky | 其他执行位 | t | T |

**所以一旦开启特殊权限后，三种用户的执行权限，用字母的大小写表示。**

**而一旦字母从“x”变为了“t/s”，就表示对应的特殊权限生效。**

**一个完整例子**假设某文件 mode 为：

```c
04755
```

ls -l 显示：

```c
-rwsr-xr-x
```

假设某目录 mode 为：

```c
01777
```

ls -l 显示：

```c
drwxrwxrwt
```

**总结**ls-l并不是单纯打印 rwx 权限。

它实际上是：

1. 读取st_mode
2. 解析文件类型位
3. 解析特殊权限位
4. 解析普通权限位
5. 组合成字符形式输出

也就是说：

```c
-rwsrwxrwt
```

本质上就是一个 mode 位字段的字符化展示。

理解这一点之后，看到s 、S 、t 、T ，你就能立刻反推出 mode 的具体数值了。

#### 10.1 创建文件

在 Linux 下创建文件的方式有多种，最常用的是以下三种方式：


2. touch 单词是触摸的意思，touch文件名... 作用是文件不存在则创建文件，若存在则将文件的最后修改时间更新。
3. vim 是后续我们最常用的方式，它也可以用于创建多个文件。关于vim的详细使用，我们在后续章节继续学习。

当你在终端输入一个命令时，系统会按照PATH环境变量中指定的顺序搜索这些目录，直到找到匹配的可执行文件为止。

在以往我们给大家演示过一个指令：./hello.py该指令用于执行一个可执行文件，那么你现在就可以思考一下这个指令为什么不能写成hello.py 直接执行这个文件呢？

这是因为直接写hello.py ，Linux会把整体当成一个指令去PATH环境变量下寻找可执行程序，但很明显这是找不到的，所以会报错：

hello.py：未找到命令而使用了./ 就不会去PATH环境变量下寻找了，而是直接在当前工作目录下，找到当前工作目录下的可执行程序进而执行。



#### 10.7 重定向指令

在Linux系统中，重定向允许改变命令的标准输入流的**输入源**以及标准输出和标准错误流的**输出目的地**。这对于保存输出结果到文件、从文件中读取输入或将一个命令的输出作为另一个命令的输入等操作非常有用。

重定向的示意图如下所示：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img029.png)

*图10.7-1重定向-示意图*

需要注意的是，重定向的含义是断开缓冲区和默认关联设备的链接，转而链接到另一个文件中，这点在图中应该很容易理解。

**注意：重定向不是改变进程和缓冲区之间的关联，而是改变缓冲区的源和目的地！！！**

在讲重定向之前，我们需要先引入文件描述符的概念，这个概念具体的内容我们会等到后面再详细讲解。现在我们只需要知道：

1. 它是一个非负整数
2. 文件描述符不同，重定向符号会有所不同。

| 标准流 | 文件描述符 | 重定向符号 |
|---|---|---|
| stdin | 0 | < |
| stdout | 1 | > 和 >> |
| stderr | 2 | 2> 和 2>> |

解释一下这些重定向符号：

1. <：将文件的内容重定向到命令的输入，一般比较少使用。
2. >：将命令的标准输出重定向到一个文件中，如果文件已经存在，则从头覆盖文件内容。
3. >>：将命令的标准输出追加到一个文件的末尾，如果文件t不存在，则创建文件。
4. 2>和2>> 类似标准输出流的重定向，只不过改成了标准错误输出。

重定向往往配合cat、head、tail、echo等命令一起使用，一些常见的使用示例如下：

```c
$ who > users #将原本输出到屏幕上的当前用户的信息输出到文件users中
$ echo "faker is a fake" >> users #将原本输出到屏幕上的字符串信息追加写入到文件users中
$ wc -l < users #将默认键盘输入重定向从文件users读取数据，它从效果上基本等价于wcusers

# 在file1不存在的前提下执行下列命令
# 此时cat指令会将users的内容输出到stdout，默认打印到屏幕
# 并且还会将file1不存在的错误信息输出到stdout，默认打印到屏幕
$ cat users file1 > text # 重定向stdout，将users文件内容打印到文件text中
$ cat users file1 2> text # 重定向stderr，将file1文件不存在的错误信息打印到文件text中
$ cat users file1 >& text # 同时重定向stdout和stderr，将文件内容和错误信息同步输出到文件text中
```

我们可以使用wc 命令进一步的来理解重定向。

#### 10.8 grep搜索文件内容(重点)

关于正则表达式，我们放到后面再具体讲解，这里我们先学习一下grep指令的基本使用——直接匹配查找目标字符串出现的行。

该指令的基本格式如下：


#### 10.9 正则表达式(重要)

正则表达式的语法还是比较复杂的，严格来说它算一门单独的课程内容，而且正则表达式的语法还存在不统一、不一致的情况。

不过好在，对于一般的程序员而言，几乎不用自己手写正则表达式，你可以通过各种正则表达式生成网站、AI工具等帮助你编写复杂的正则表达式。

但完全不懂正则表达式的语法，完全看不懂正则表达式也不行，所以我们在这里讲解一些正则表达式的基本语法、核心语法，以帮助大家能够看懂基础的正则表达式，这就是我们对大家的要求。

正则表达式的基础语法基于三个核心的概念：

1. 基本单位
2. 基本操作
3. 基本单位出现的位置

下面逐一解释这三个概念：

##### 10.9.1 基本单位

正则表达式的基本单位包含：

1. 单个字符：直接匹配文本中的特定字符。例如，a匹配字符 "a"。
2. 字符(点字符)：匹配除换行符以外的任何单个字符。例如，a.b可以匹配"acb"、"a&b"、"a9b" 等。
3. * 字符(星号字符)：匹配**前一个**字符零次或多次。例如，ho*会匹配 'h', 'ho', 'hoo', 'hooo' 等。
4. 转义字符\ ：通过在特殊字符前加反斜线\来取消这些字符的特殊含义，使其能够被直接匹配。例如\.匹配实际的点字符 "."。
5. 集合，比如[abc]、[^abc]，使用[...]来匹配指定集合内的任意**单个字符**或者^取反表示任何集合外的单个字符。
6. 分组(expr)，将expr视为一个单独的单位，允许对整个表达式应用重复操作等。

例如，(abc)+匹配一个或多个连续的 "abc"。

任何复杂的正则表达式都是由以上基本单位组成的。

##### 10.9.2 基本操作

基于基本单位，可以执行基本操作，从而获取更复杂的匹配逻辑。基本操作比较常用的有两个：

**连接：简单地将两个或更多的基本单位放在一起，表示按照顺序匹配。**例如：

1. "abc"这个正则表达式就是匹配字符串"abc"，它连接了多个单个字符。
2. "[abc]x"集合和单个字符连接，表示可以匹配"ax"、"bx"以及"cx"。
3. ".txt"是什么意思呢？是匹配所有以.txt结尾的字符串吗？
   - a. 当然不是，不要挖个坑就跳下去了。
   - b. 字符的作用是匹配除换行符之外的任何单个字符。
   - c. 所以这里是匹配诸如"atxt"、"btxt"、"ctxt"等这样的字符串。
   - d. 思考一下，若想获取匹配".txt"的正则表达式，怎么办？答：\.txt

**重复：指定一个基本单位重复出现的次数。**例如：

1. + ：表示至少出现一次。例如：
   - a. a+匹配 "a"、"aa"、"aaa" 等。
   - b. abc+ 表示单个字符c 至少出现一次。于是可以匹配"abc"、"abcc"、"abccc" 等。
   - c. [abc]+ 表示集合[abc] 至少出现一次，这样匹配的内容就很多了，只要是包含一个或多个 "a"、"b" 或 "c" 的字符串都可以。比如"a"、"ab"、"bca"、"cba"、"cccbbaaa" 等。
   - d. (abc)+ 表示分组(abc) 至少出现一次。所以就匹配"abc"、"abcabc"、"abcabcabc"等这样的固定abc序列。
2. ? ：重复零次或一次。例如：
   - a. abc? 即匹配"ab"和"abc"
   - b. [abc]? 即匹配""、"a"、"b"或者"c"
   - c. (abc)? 即匹配""或者"abc"
3. * ：重复任意次数，可以是零次，一次或多次。例如：
   - a. abc* 即匹配"ab"、"abc"以及"abcc"....
   - b. [abc]* 即匹配""、"a"、"b"、"c"以及包含多个 "a"、"b" 或 "c" 的字符串
   - c. (abc)* 即匹配""或者"abc"以及更多abc组成的序列
   - d. .* 表示匹配任意文本内容。
4. 你还可以在基本单位后面加{m} 以更精确的控制重复次数：
   - a. {m} ：重复 m 次。
   - b. {m,n} ：重复 [m, n] 次。
   - c. {n,} ：至少重复 n 次，即重复[n, 正无穷)次。

##### 10.9.3 基本单位出现的位置

**明确基本单位是什么，也搞清楚基本单位出现的规则和次数，那么接下来只需要搞清楚基本单位出现的位置，一个具有复杂匹配功能的正则表达式就诞生了。**

grep 指令是一行一行匹配的，所以重要的、常见的位置有下面情况：

1. ^ ：匹配行的开始，行首。例如，^abc匹配任何以 "abc" 开始的行首。
2. $ ：匹配行的结束，行尾。例如，xyz$匹配任何以 "xyz" 结尾的行尾。
3. \< 、\> ：分别匹配一个单词的开始和结束。单词同样是基于空格、制表符间隔去判断的。

比如我想匹配一行，该行以".txt"结尾，怎么办？

答：\.txt$

创建一个text文件，其文件内容如下：

执行以下grep指令，分析结果：

实际结果如下：

### 11. 命令的组合(重要)

shell命令是可以进行组合使用的，基于命令的组合，可以增强一些指令的作用。比如grep，就可以利用组合命令，大大增强它的功能。

命令的组合主要有三种方式：

1. cmd;cmd2 ，即两条指令间使用分号隔开，这个组合很简单就是单纯的先执行命令1，然后执行命令2。例如：
   - a. mkdirdir;cddir
   - b. 先创建dir目录，然后cd进入该目录
2. cmd1|cmd2 ，其中"|"是管道，整个命令表示将cmd1指令输出的结果，作为cmd2指令的输入。
3. cmd1|xargscmd2 ，表示将cmd1输出结果的每一行作为cmd2指令执行的输入参数。

第一种组合方式比较简单，不再赘述，下面两种方式我们专门讲解一下。

#### 11.1 管道

`|` 是字符**竖线**，不是大写字母I，它表示管道，管道是进程间通信的一种方式，从效果上看：

cmd1|cmd2 就表示将cmd1指令执行的输出结果，作为cmd2指令的输入。

管道在这里是什么原理呢？

cmd1 和cmd2 指令的执行实际上是启动了两个进程，整个管道的原理如下图所示：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img034.png)

*图11.1-1管道-示意图*

管道是操作系统内核提供一种系统功能，它可以被想象为一个缓冲区队列，用于存储从管道一端输入的数据，直到另一端的进程读取它。

管道允许数据从一个进程流向另一个进程，是进程间通信的重要手段。

具体到cmd1|cmd2 指令：

cmd1指令的进程会将stdout输出重定向到管道中，也就是cmd1进程的输出不再打印到屏幕上，而是将数据放入管道；

cmd2指令的进程会将stdin输入重定向到同一管道中，也就是cmd1进程的输入不再是从键盘接收录入，而是从管道读取数据。

于是cmd1|cmd2 指令就实现了：

将cmd1指令的输出结果，作为cmd2指令的输入数据。

#### 11.2 管道 "|" 应用举例

history 指令会将当前会话输入的shell指令的历史输出到stdout中，进而打印在屏幕上。

tail-n5 指令在不输入文件名的情况下会从stdin接收数据(默认是从键盘)，然后将后5行输出到stdout中（默认是输出到屏幕中）。

现在把它们用管道组合起来，得到组合指令：

history|tail-n5效果是什么呢？

很简单：

history 指令的输出作为tail-n5 指令的输入，总的效果就是打印shell指令历史的后5行。

**再举一些例子：**

ls-lh|grep-E"test" ：列出当前目录的详细列表，并通过grep 搜索包含"test"的行。

ll|head ：有些时候目录下的内容很多，可以用这种方式只看目录下的前十个文件内容。当然你可以使用tail，显示后十行。

tail-fserver.log|grep-niE"error" ：持续显示系统日志文件中最新的内容，并且只显示包含"error"的行。这个指令可以使用：

echo"Thisisanerrortest">>server.log 来模拟日志文件追加写入，然后进行测试。

#### 11.3 管道 "| xargs" 应用举例

xargs 是词组"extended arguments"的缩写，意为扩展的参数。

组合命令cmd1|xargscmd2 的含义是：将cmd1指令输出的每一行（或者以空格、制表符分割），作为参数，然后传递给cmd2指令进程。

使用举例：

比如现在的需求是：查找当前目录下所有的.c文件，然后找到文件内容中存在main函数的行。

这明显是一个组合需求：

1. 查找当前目录下所有的.c文件：可以用指令find.-name"*.c"
2. 查找某个.c文件中存在main函数的行：可以用指令grep-nE"\<main\("xxx.c

利用xargs和管道，我们可以将这两个指令组合，得到指令：

find.-name"*.c"|xargsgrep-nE"\<main\("就可以实现需求了。

那么思考一下：

find.-name"*.c"|xargsgrep-nE"\<main\("和find.-name"*.c"|grep-nE"\<main\("有什么区别呢？

后者实际上是一个误用，它会导致find 的所有输出都作为grep 的一个输入参数，这是不行的。

**再举一些例子：**

`|xargs` 和 rm 连用，可以实现根据条件删除目标文件，比如：

find~-typef-size+100M|xargsrm ：删除家目录下所有大于100Mb的普通文件find.-typef-name"*.c"|xargsrm ：删除当前目录下所有的".c"结尾的普通文件

#### 11.4 "| xargs"的原理（扩展）

首先要搞清楚一个事情："xargs"是什么？

实际上"xargs"也是一个shell指令，**直接执行这个shell指令**会从标准输入stdin中读取数据，并将这些数据转换成一个一个的参数，并输出到标准输出当中。具体而言，会以空白字符（空格、换行以及制表符）为间隔划分参数，输出到标准输出中。

该指令的演示效果如下图所示：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img035.png)

*图11.4-1"|xargs"的原理-图1*

所以，**"cmd1 | xargs"**实际上就已经是两个进程间利用管道通信：

1. cmd1指令的进程会向标准输出stdout中输出数据，现在将标准输出重定向到管道
2. xargs进程会从标准输入stdin中读数据，现在将标准输入重定向到管道

这样，cmd1进程的输出结果就成为了xargs指令进程的输入，示意图如下：

![](Linux_assets/卷一%20Linux基础/03_常用shell命令/img036.png)

*图11.4-2"|xargs"的原理-图2*

xargs进程得到cmd1进程的输出作为输入后，执行什么样的操作呢？

或者说，xagrs进程和cmd2进程之间是什么关系呢？它们之间还是基于管道的进程间通信吗？

实际上，xagrs进程和cmd2进程之间是没有进程间通信的，因为它们中间没有"|"，没有使用管道。xagrs进程和cmd2进程之间，是一种"父子进程"的关系：

1. xargs通过管道从另一个命令cmd1 中获得数据输入，接着xargs 进程解析这些数据，基于空格、制表符或换行符将数据分割成多个部分。
2. 这样操作后，xargs进程就得到了分割好的数据参数，xargs进程会将这些数据参数构造成**命令行参数（就是程序入口函数接受的命令行参数）**。
3. **基于这个命令行参数，xargs进程会将参数传递并启动cmd2进程。**
4. 在这个过程中，由于cmd2进程由xargs传参启动，cmd2进程就是xargs进程的子进程。**（Linux的shell指令背后的可执行程序基本上都是C程序）**

基于以上原理，我们可以详细的分析一下指令：

find.-name"*.c"|xargsgrep-nE"\<main\( 的执行过程：

```c
find . -name "\*.c"
```

   - a. 此命令在当前目录及其所有子目录中，递归搜索所有扩展名为.c的文件。
   - b. 找到的每个文件路径名都会输出到标准输出中，并且一行输出一个文件路径名。

```c
| xargs
```

   - a. find 命令的输出本身会默认输出到显示器终端上，但管道操作符使得这个输出被重定向到了管道中
   - b. xargs 进程本身要从标准输入中读取数据，默认从键盘接收输入，但管道操作符使得这个输入被重定向到了管道中
   - c. 于是find 进程输出的文件名列表，就作为了进程xargs 的输入
   - d. xargs会把接收到的每一行文件路径名，分割好然后构建成命令行参数。

```c
grep -nE "\<main\(
```

   - a. 该指令本身会启动执行grep 进程，从标准输入中查找符合正则表达式规则的内容。
   - b. 但由于|xargs 结构的影响，xargs 进程会把构建好的**文件路径名的命令行参数**传递给grep程序，然后启动grep进程
   - c. 于是，这个grep 进程会将find 进程搜索到的结果文件路径名的每一行，都视为一个需要搜索的文件，挨个完成搜索。
4. 最终，这个命令组合的含义是：查找当前目录下所有的.c文件，然后找到文件内容中存在main函数的行。

以上。

### 12. 创建硬/软链接

我们可以用ln指令创建硬链接和符号连接(软链接)，它是单词link 的简写。下面分别讲解一下这两种语法：

#### 12.1 创建硬链接

创建硬链接的指令格式如下：

ln target_file link_name #创建一个目标文件的硬链接解释：

1. target_file是你要硬链接的原始文件的名字
2. link_name是硬链接的名字

举个例子：

ln test link_test #创建test文件的硬链接link_test表示为test文件创建一个硬链接link_test，此时这两个文件会共用同一个inode。

**注意：**

1. 硬链接直接指向文件的磁盘位置（inode），因此原始文件和硬链接实际上指向相同的物理位置。**此时修改任意文件内容，其余文件内容会一起被修改。**
2. 硬链接不允许链接向目录，这是为了防止破坏目录结构的设计以及避免出现目录访问死循环。
3. 为文件创建硬链接后，文件的硬链接数就会增加。当硬链接数为 0 的时候，才会真正删除磁盘上的文件。

#### 12.2 创建软链接

创建软链接的指令格式如下：

ln -s target_file slink_name #添加一个选项-s，表示soft软链接解释：

1. target_file是你要硬链接的原始文件的名字
2. slink_name是软链接的名字

软链接，也就符号链接，可以视为Windows系统中快捷方式或者C程序中的指针，指向另一个文件或目录。

举个例子：

```c
ln -s test slink_test
```

表示为test文件创建一个软链接slink_test，它是独立的软链接文件，有自己独立的inode，此时访问slink_test就是访问原文件test。

如果删除软链接文件，原文件不受影响。

如果删除原文件，那么软链接文件就会指向一个不存在的文件，成为一个"死链接"，类似空指针。

**软链接可以链接到目录或者文件。**

硬链接和符号链接的原理如下图所示：

*图12.2-1软硬链接的原理-图*

**对于大多数命令(rm除外)，如果参数是符号链接，其实操作的是符号链接指向的文件(类似指针的解引用操作)：**

```c
$ echo "I love xixi\n" > text
$ ln -s text s_link
$ cat s_link #输出结果是：I love xixi
$ rm s_link # 删除符号链接文件本身，而不是它指向的文件
```

符号链接要使用的比硬链接多得多。

### 13. 远程复制指令（了解）

scp （Secure Copy）是一种在本地和远程计算机之间进行安全传输文件的工具。它基于 SSH（Secure Shell）协议，提供与 SSH 相同的安全性和认证特性，确保传输过程中的数据加密和安全。

在Windows和Linux都可以使用该指令进行远程的上传和下载：

1. 上传：将本地的文件复制到远程
2. 下载：将远程的文件复制到本地

scp指令的使用和cp指令非常类似，本质上都是把src复制到目标dest，具体格式如下：

```c
$ man scp
    scp -- secure copy (remote file copy program)
    #远程的安全的加密复制
格式：
    scp [选项] SRC... DEST
    #本地路径：可以用绝对路径，也可以用相对路径
    #远程路径：用户名@IP:路径
常用选项：
    -r #递归复制整个目录
```

一些使用举例：

```c
scp wgd@IP:~/text1 . # 将wgd用户家目录下的text1文件下载到当前工作目录,在Windows的cmd命令行中执行
scp ./file wgd@IP:~ # 将当前工作目录下的file文件上传到wgd用户的家目录下,在Windows的cmd命令行中执行
```

### 14. 归档压缩指令（了解）

tar指令一开始是用于创建、维护、修改以及提取 tar 归档文件的指令，所谓归档文件是一种将多个文件和目录（文件夹）组合成一个单一文件的方式。

但归档这种合并文件的操作使得它天然就适合同时进行压缩操作，所以但到如今，你完全可以直接将tar 指令理解成压缩和解压缩指令，我们日常使用该指令也是用于压缩和解压缩的。

其使用的格式如下(这里只列出打包压缩相关的)：

tar [主选项+辅选项] 包名 [文件或目录]..

解释：

1. **主选项(有且只能选择其中一个)：**
   - a. c: 创建：创建新的归档文件。如果归档文件已存在，则此选项将覆盖原有文件。
   - b. r: 追加：追加文件到已存在的归档文件末尾。如果归档文件不存在，则会报错。

**注意若归档文件已压缩，需要先释放再追加。**

   - c. x: 释放：释放（解压）归档文件中的内容。这会根据归档中的结构恢复文件和目录。
   - d. t: 查看：查看归档内容，列出归档文件中包含的文件和目录，但不提取它们。
2. **辅选项：**
   - a. f: 指定包文件的名称：**该辅助项选择一般是必加的**，用于指令下一个参数是归档文件的名字。否则tar无法得到哪些属于被归档文件，哪个是归档的结果。
   - b. v: 显示处理过程的详细信息。如果是查看归档文件，则显示文件的详细信息。**该指令一般也建议都加上。**
   - c. z: 使用gzip算法压缩或解压缩归档文件。

常见用法举例：

```c
tar cfv package.tar test* #归档所有以test开头的文件/目录，但不压缩
tar tfv package.tar #查看归档文件package.tar中的文件详细信息
tar rfv package.tar The_Holy_Bible.txt #向归档文件package.tar中追加一个文件
tar cfvz package.tar.gz test* #归档并压缩所有以test开头的文件/目录，得到的归档文件会比上面得到的更小
mv package.tar.gz dir #将压缩后的归档文件移到到一个新目录
tar xzvf package.tar.gz #释放(解压缩)package.tar.gz压缩文件
```

注意：

1. 未压缩的归档文件建议命名为.tar 结尾，而使用使用gzip算法压缩的归档文件建议命名为.tar.gz结尾。
2. 已经压缩的归档文件不能直接使用tarrxxx 追加新文件，需要先解压缩后重新压缩生成新文件。

## 04 Vim编辑器

### 1. 概述

**Vim(Vi improved)**是一款从 Vi 发展出来的一个文本编辑器。

它的最大特点是模式化以及指令化，这使得Vim在熟练的程序员手中可以极大的提升编码的效率。

比起传统的文本编辑器，如：VS Code、Word、Nodepad++和Sublime Text等：

Vim这种指令化的编辑器确实存在上手困难，初期使用难受的缺点，但一旦熟练使用Vim，基本可以全程摆脱鼠标进行编码，效率大增。

所以Vim 在程序员中使用地非常广泛，和 Emacs 并称为类 Unix 系统用户最喜欢的文本编辑器。事实上，这两大编辑神器之间的圣战一直没停歇过。

**在这个蔚蓝色的星球上，流传着两大神器的传说：据说 Emacs 是神的编辑器，而Vim 是编辑器的神...**

### 2. Vim的模式

Vim 是一种多模式的文本编辑器，它与我们熟悉的"所见即所得"的编辑器不太一样。

Vim 在不同模式下有不同的功能，拥有不同的指令，这也是 Vim 之所有这么强大的重要原因。

Vim 有非常多种模式(总有个七八种以上)，但常用的只有三种模式(其实**最常用只有两种，普通和插入**)：

1. 普通模式，也叫指令模式。
   - a. 该模式可以通过输入一些指令，进行一些控制操作。
   - b. **普通模式是Vim的灵魂与核心，学习普通模式的使用是学习Vim最重要的部分！**
2. 插入模式，也叫编辑模式。编辑模式就是一种"所见即所得"的模式，以往我们使用过的编辑器都是这种模式。
3. 视图模式，也叫视觉模式。**视图模式主要用于选择范围，谈不上很常用，但一定要会！！！**

这些模式之间可以相互转换，如下图所示：

![](Linux_assets/卷一%20Linux基础/04_Vim编辑器/img001.png)

*图2-1Vim的三大常用模式-图*

显然普通模式是模式转换的核心，想要切换到其它模式，一般都需要先使用ESC 回到普通模式。

如果希望从普通模式切换到插入模式，按键有：

1. i: 在光标前面插入
2. I(大写字母i): 在行首插入
3. a: 在光标后面插入
4. A: 在行尾插入
5. o: 在下面另起一行，并在行首插入
6. O: 在上面另起一行，并在行首插入

如果希望从普通模式切换到视图模式，按键有：

1. v: 进入行选模式
2. Ctrl + v: 进入竖选模式，或者块选模式。

当你处在插入模式或视觉模式下时，只需要按退出ESC键，就可以立刻回到普通模式。

**使用Vim时，我们应该在多数情况下使Vim处于普通模式，而不是插入模式，这是一个很好的习惯。**

###### 为什么要习惯性的将Vim切换到普通模式呢？

Vim 的设计哲学是让用户能够以最少的按键完成最多的编辑任务。

普通模式是 Vim 的核心模式，提供了丰富的命令来移动光标、复制和粘贴文本、搜索和替换文本等等，而无需额外的按键或者切换到其他模式。

保持在普通模式下可以帮助你更快地完成编辑任务，同时减少误操作的机会。

在普通模式下，除了添加或修改文本内容外的编辑任务，都可以通过指令完成，这非常好用。

因此，养成在完成插入或修改内容的操作后立即返回普通模式的习惯是很重要的。

### 3. 利用Vim打开文件

若想要使用Vim编辑一个文件，就首先需要用vim 指令打开这个文件。如下：

```c
vim [文件名]
```

vim这个指令没有什么常用的选项，偶尔会用到的有：

**+n**：将光标定位到文件的第 n 行。例如，vim+10hello.c将光标定位到hello.c文件的第 10 行。

当我们使用vim文件名打开了一个文件后，可以输入以下长命令来实现一些对文件的操作：

| 命令 | 含义 |
|---|---|
| :w | 将buffer里面的内容写入文件，即保存文件 |
| :q | 退出 |
| :q! | 不保存退出 |
| :wq | 保存退出 |

注意：

ctrl+s没有保存的效果，不要总是顺手按这个快捷键，它会使Vim进入僵死状态。

ctrl+q可以退出僵死状态，而且退出时会一股脑输出之前僵尸状态输入的信息。

### 4. 普通模式(核心)

普通模式也叫命令模式，顾名思义，这种模式就是用来执行各种命令的。我们学习Vim，最核心的就是学习Vim普通模式下的指令。

这些命令又分为短命令和长命令：

1. 长命令：所有以 `:` 开头，以回车结尾的命令都是长命令。最常用的当属保存并退出指令：`:wq` 回车。

2. 短命令：不是长命令就是短命令。比如我们用过的删除当前行d 指令，组合指令dj 等。

**注意：如果没有特别备注大小写均可，那么该指令是区分大小写的！！！**

在具体学习各种指令之前，我们先给大家讲一些学习理解和记忆指令的技巧。

#### 4.1 技巧相关

**第一：Vim的指令是可以组合的，将命令组合起来可以得到一个新的命令。**

Vim指令的组合是有规律的。举两个例子：

1. 在 Vim 中，"d" 表示删除当前行，"j" 移动到下一行，于是组合 "dj" 表示删除当前行和下一行。
   - a. 这种组合是基于"action + motion"的，即将动作和移动方向进行组合。
   - b. **再比如："^" 代表行首，故组合 "d^" 表示删除到行首；"$" 代表行尾，"d$" 表示删除到行尾。**
2. 另一种常见的组合方式是"num + action"，即数字和动作的组合，表示动作重复的次数。
   - a. 比如"dd" 表示删除光标所在行，"2dd" 或 "d2d" 表示连续删除两行，效果和 "dj" 一致。

**第二：Vim普通模式下的指令**如果某个功能的指令是具有方向的，并且它用相同字母的大小写来代表不同的方向，那么普通的规律是：

1. **小写字母代表的方向是向右、向后、向下**
2. **大写字母代表的方向是向左、向前、向上**

#### 4.2 移动光标指令

**首先，我们要清楚在Vim下，我们的光标默认是方块状的，它会包含某个字符。**

移动光标属于命令当中"motion"类，这些指令都必须要熟悉、而且要熟练使用。

**第一类：上下左右移动光标一个字符。**

| 命令 | 含义 | 备注 |
|---|---|---|
| h | 往左移动一个字符 | 相当于小键盘方向键，向左 |
| j | 往下移动一个字符 | 相当于小键盘方向键，向下 |
| k | 往上移动一个字符 | 相当于小键盘方向键，向上 |
| l(小写字母L) | 往右移动一个字符 | 相当于小键盘方向键，向右 |

虽然**小键盘方向键上下左右**也完全可以实现hjkl 的功能，而且大家也早已习惯这么做，但仍然可以学习一下这四个Vim中的方向键！

如何记忆这些指令呢？

1. 首先，记住上下左右都在一行，而且是键盘从左往右分别是：hjkl
2. h 在最左边，所以它表示向左移动光标一个字符。
3. l 在最右边，所以它表示向右移动光标一个字符。
4. j 强行记住它是向下的。
5. k 强行记住它是向上的。

**第二类：光标直接移动行。**

| 命令 | 含义 | 备注 |
|---|---|---|
| [n]- | 往上移动n行 | 不太常用，了解即可 |
| [n]+ | 往下移动n行 | 不太常用，了解即可 |
| :[n] 或 [n]G | 移动到第n行 | :[n]这个建议记一下 |

**第三类：光标直接移动到文件第一行和最后一行。**

| 命令 | 含义 | 备注 |
|---|---|---|
| gg | 移动光标到第一行 | 一局游戏打出"gg"，表示再来一把。所以是移动到文件开头 |
| G | 移动光标到最后一行 | 这个也比较常用，要记住它。 |

**第四类：光标在这一行的内部移动(重要)**

| 命令 | 含义 | 备注 |
|---|---|---|
| ^ | 移动光标到当前行的第一个非空白字符处 | 更常用一些 |
| 0 | 移动光标到当前行的行首 | 知道即可 |
| $ | 移动到行尾 | 谈钱伤感情，所以谈钱就表示行结束了，行尾 |
| w | 光标移动到下一个单词的词首 | 多练强行记住，很有用 |
| b | 光标移动到上一个单词的词首 | 多练强行记住，很有用 |

**第五类：移动光标到某个固定字符（重要！）**

| 命令 | 含义 |
|---|---|
| t) | 向后查找，将光标移动到)的前一个字符 |
| f) | 向后查找，将光标移动到) |
| T" | 向前查找，将光标移动到"的后一个字符 |
| F" | 向前查找，将光标移动到" |

这四个指令具有以下特征，方便你记忆：

1. 小写都表示向后查找，大写都表示向前查找。
2. t/T 表示将光标移动到目标字符前/后一个字符，f/F 都表示将光标移动到目标字符。
3. **注：命令行我们使用的光标是块状的，建议大家记f，因为f/F会包含目标字符，这在执行删除操作时特别好用。**

#### 4.3 删除文本指令

删除的所有命令都属于action，这意味着我们可以通过"action + motion"的方式得到一些组合命令。

必须需要注意的是：

**Vim的删除操作类似Windows系统中的剪切操作，会将删除的内容复制到 Vim 的"剪切板"中，并且可以粘贴出来，粘贴的命令是P/p(paste)。**

删除的指令有以下，其中核心的字符是d ：

| 命令 | 含义 |
|---|---|
| x | 删除一个字符 |
| db | 从光标的下一个元素删除到上一个单词的词首(上一个单词的词首会被删除) |
| dw | 从光标元素开始删除到下一个单词的词首(下一个单词的词首不会被删除) |
| diw | 删除光标所在的整个单词，但不包括单词周围的空格。 |
| di" | 删除光标所在""范围内的所有内容 |
| dd | 删除当前这一行 |
| [n]dd | 删除当前和下面的(n-1)行，共n行被删除 |
| :[m],[n]d | 删除文本的[m,n]行 |
| d^ | 删除到行首(不删除光标位置的字符) |
| d$ | 删除到行尾(删除光标位置的字符) |
| df) | 向后删除直到)，同时删除)和光标位置字符 |
| dt) | 向后删除直到)同时删除光标位置字符，但不删除) |
| dT" | 向前删除直到"但不删除"和光标位置字符 |
| dF" | 从光标位置元素(不包含)开始向前直到"(包含)全部删掉 |

建议：

1. 命令组合的格式是action+motion ，所以总是d在前，因为它是action动作。
2. 建议记住df) 这个指令，其它的不要记，尤其是T/F 这种，太逆天了。
3. df 是向后删除直到目标字符，而且是光标字符和目标字符都删除，很好记忆。利用这个指令，可以删除""、()、{}内的所有内容。

#### 4.4 粘贴，撤销和重做指令

d 操作的所有删除都相当于把删除内容剪切到Vim的"剪切板"上，所以这里我们看一下粘贴的相关指令。

**粘贴，撤销和重做相关的Vim指令：**

| 命令 | 含义 | 备注 |
|---|---|---|
| p | 粘贴到下一行(如果复制的是行的话) | 如果复制的不是行，那就粘贴到光标后面 |
| P | 粘贴到上一行(如果复制的是行的话) | 如果复制的不是行，那就粘贴到光标的前面 |
| u | 撤销(undo) | 相当于Windows中的Ctrl + Z |
| Ctrl + r | 重做(redo) | 相当于Windows中的Ctrl + Shift + Z |

注意：

所谓重做，就是**"将撤销操作撤销"**，你试一下就知道了，注意这些指令都要区分大小写。

#### 4.5 修改文本指令

Vim的修改文本指令，从指令组合的形式上来说仍然属于"action + motion"的组合方式。从效果上来说其实就是删除操作和进入编辑模式两个操作的组合。

这种类型的指令有：

| 命令 | 含义 |
|---|---|
| cc 或 S | 删除当前行，并进入编辑模式 |
| [n]cc 或 [n]S | 删除n行，并进入编辑模式 |
| cw | 删除一个单词，并进入编辑模式 |
| [n]cw 或 c[n]w | 删除n个单词，并进入编辑模式 |
| c^ | 删除到行首，并进入编辑模式 |
| c$ | 删除到行尾，并进入编辑模式 |
| ct) | 删除到)，并进入编辑模式 |
| ct" | 删除到"，并进入编辑模式 |
| c[n]G | 删除到第n行，并进入编辑模式 |
| cG | 删除到文件末尾，并进入编辑模式 |
| ci" | 当光标处在""当中时，删除整个""内容并进入编辑模式 |
| ciw | 删除光标所在的整个单词，但不包括单词周围的空格，并进入编辑模式 |

在很多时候，我们还是更倾向于先在普通模式下执行各种删除操作，然后再使用

   - a. io 等指令进入到插入模式。

所以修改文本指令当中，我们仅要求大家掌握一个指令：

**ci"、ci(、ci)、ci{、ci}、ci'、ciw**这个指令的强大之处在于，只要光标处在某个区域内，就可以直接的快速删除区域内的所有内容，特别好用！

#### 4.6 复制文本指令

复制文本的指令基于y 字符，有以下这些：

| 命令 | 含义 | 备注 |
|---|---|---|
| yy | 复制当前行（包括换行符） | yyp可实现快速复制当前行到下一行，非常常用！ |
| [n]yy | 复制从当前行开始的下面n行，包括当前行自身 | 一共复制了n行 |
| :[m],[n]y | 复制[m,n]行 | 长命令，输入命令后要按回车执行（常用！） |
| yw | 复制直到下一个单词词首 | 包含光标位置字符，不包含下一个单词的词首 |
| yf) | 复制到) | 包含光标位置字符，也包含) |

最需要记住的就是yyp ，其它的可以练习练习，作为了解。

#### 4.7 查找文本命令

在Windows系统中，一般的文本编辑器都可以使用Ctrl+F 来进入搜索文本的模式。

Vim也有类似的功能，而且Vim在查找文本内容时，可以基于正则表达式，所以功能实际上会更强大。

具体的指令如下：

| 命令 | 含义 | 备注 |
|---|---|---|
| /pattern | 从光标所在位置向后查找匹配pattern的内容，pattern为正则表达式 | /pattern指令输入后要回车表示开始搜索 |
| ?pattern | 从光标所在位置向前查找匹配pattern的内容，pattern为正则表达式 | ?pattern指令输入后要回车表示开始搜索 |
| n | 移动到下一个匹配项 | 上面指令回车后，才可以开始移动 |
| N | 移动到上一个匹配项 | 上面指令回车后，才可以开始移动 |

pattern可以直接写要匹配的目标字符串，比如要查找目标字符串"hello"，就可以直接写指令/hello 然后回车即可。

记忆点：大写n表示向前，小写n表示向后。

**实际上，代码中去查找内容，基本上都是基于字符串内容直接查，几乎不会用到复杂的正则表达式。**

#### 4.8 替换文本指令

在Windows系统中，一般的文本编辑器都可以使用Ctrl+R 来进入搜索并替换文本的模式。

Vim编辑器当然也有这样的功能，Vim中的替换指令核心字符是s ，它是单词"substitute"的缩写。替换指令属于长指令，所以要以: 开头。

具体的指令有以下几种格式：

1. :s/pattern/substitute ：只会替换光标所在行的第一个匹配项
2. :s/pattern/substitute/g ：替换光标所在行的所有匹配项
3. :[m],[n]s/pattern/substitute/g ：替换[m,n]行的所有匹配项
4. :%s/pattern/substitute/g ：替换全文的所有匹配项
5. :%s/pattern/substitute/gc ：替换全文的所有匹配项，但每个位置都会逐一询问是否替换。

注：

1. /c 标志可以加在上面指令任意一条中，作用是在替换之前询问。这在需要精准控制替换时，特别有用。
2. 语法中的分隔符都是/ ，如果匹配的内容中有/ ，那就使用转义字符\ 。比如若想匹配/a/ ，那就需要写\/a\/

#### 4.9 其它常用指令

1.自动代码对齐：gg=G2.使用gi命令快速返回到上次插入文本的地方并进入插入模式。

3.[[和]] ：移动到代码的上一个或下一个函数（假设每个函数由大括号定义并且大括号会换行）。

4.使用~可以改变当前光标字符的大小写，或者在可视模式中选择多个字符后按~来批量改变大小写。

5.使用q:打开命令行窗口，这样可以浏览历史命令并进行编辑。这对于修改或重用长命令特别有用。然后再q会退出6.使用%可以在匹配的括号之间跳转，如(和) ，{和} ，或[和] 。这在编程时检查代码块的开始和结束非常有用。

(Rd!)**以上，关于普通模式下的一些常用指令就已经讲完了。剩下的就要靠大家自己多练习了。**

### 5. 视图模式

视图模式是用来选择内容的，选择内容之后，我们就可以对选中的内容进行复制或删除操作了。

从普通模式切换到视图模式，按键有：

1. v: 进入行选模式
2. Ctrl + v: 进入竖选模式，或者块选模式。

选择文本成功后：

1. 就可以用d 删除选中文本。
2. 就可以用y 复制选中文本。

###### 一个常见的使用举例：批量注释多行代码，以及释放注释

批量注释多行代码：

1. 先跳到你希望多行注释的起始行的行首，这可以使用长指令:n 回车来完成。
2. Ctrl + v: 进入竖选视图模式。
3. 使用小键盘，移动光标选中要注释的范围行。
4. 输入大写字母"I"(i的大写，一定要大写)。
   - a. 视图模式输入大写I将进入插入模式
   - b. 此时你输入的任何文本将在每行选中的同一列位置插入
   - c. 这样就能够实现多行注释了。
5. 输入注释的格式//
6. 按退出键位ESC

反之，批量释放多行注释会更简单一些：

1. 先跳到你希望释放的多行注释的起始行的行首，这可以使用长指令:n 回车来完成。
2. Ctrl + v: 进入竖选视图模式。
3. 移动光标选中要释放注释的范围行，选中所有的// 。
4. 直接按d 将所有的// 全部删除。

这个操作一定要学会，因为注释多行以及释放多行，是编码过程中非常常见的做法！

### 6. 插入模式

插入模式就不用具体讲使用了，它"所见即所得"，大家以往使用的编辑器都是这种模式，你已经很熟悉了。

稍微需要注意的是：

在Vim的插入模式下进行文本编辑时并不是直接作用于原始文件，而是在Vim的内存缓冲区当中进行编辑：

当你使用vim 打开或创建一个文件时，Vim会读取这个文件的内容到内存缓冲区中。

然后你对文件的所有修改**（无论是在插入模式还是其他模式中）**都是对这个内存中的缓冲区进行的。

当你使用:w 指令保存修改时，Vim 会将内存缓冲区中的数据写入到一个新文件中，然后移除删除旧文件，然后将新文件重命名为原始文件名。

了解这个过程可以帮助你理解Vim的一些行为。

### 7. Vim常用操作总结(重点)

我们已经很熟悉在Windows下的VS当中进行C语言开发了，下面我们就一起回顾一下有哪些操作是特别常见的，并总结如何使用Vim来更快速的实现相同的效果。

**VS中常见的操作以及它们在Vim中快速的实现指令如下，如无特别说明指令都是普通模式下的指令：**

1. 复制当前行到下一行："yyp"
2. 删除当前行：dd
3. 撤销和重做：u表示撤销，重做Ctrl + r
4. 移动到文件开头和末尾：gg移动到文件开头、G表示移动到文件的末尾
5. 移动到当前行首和行尾：0或者^表示移到到行首，$移动到末尾(^移到行首第一个非空字符，0是真正意义上的行首)
6. 全文清空：推荐ggdG，也可以用ggcG，这样会直接进入编辑模式。
7. 光标快速到达某一行开头：推荐执行长指令:n 回车，表示到达某行的开头
8. 光标快速到达某一行末尾：推荐执行长指令:n 回车，表示到达某行的开头，然后再按$ 表示跳到行尾
9. 清空""内的内容：推荐将光标移到""内部，然后使用ci"
10. 清空()内的内容：推荐将光标移到()内部，然后使用ci( 或者ci)
11. 从当前光标字符开始，删除到目标字符：
   - a. 推荐使用指令df目标字符
   - b. **这个指令的好处在于，你可以直接记住：该指令的删除包含光标字符以及目标字符！**
12. 复制整个函数的代码到下面，这个操作实际上就是复制[m, n]内的代码，然后粘贴到下面。具体的操作步骤如下：
   - a. 先复制[m, n]内的代码，使用长指令:m,ny 回车复制
   - b. 然后将光标移动到函数体的}行首，}一般会单独占一行，所以可以直接使用长指令:n 回车跳转
   - c. 按p将内容复制到下面
   - d. 注：如果你希望整个函数复制到上面，那就跳到函数声明行的行首，然后按P
13. 删除[m, n]行内的代码，推荐使用长指令:m,nd 回车删除
14. 快速单行注释，释放单行注释：快速到达某行的开头或末尾，添加//或删除//，你可以自行测试一下。
15. 搜索[m,n]行的某个内容，然后全部替换。推荐使用长指令:m,ns/旧字符串/新字符串/g
16. 全文替换。推荐使用长指令:%s/旧字符串/新字符串/g 。这些替换如果希望能够逐个选择，可以添加标记/c 。
17. 自动代码对齐：gg=G ，跳回上一次编辑的位置，使用gi命令。
18. 使用~可以改变当前光标字符的大小写，或者在可视模式中选择多个字符后按~来批量改变大小写。

快速多行注释，方式有很多，但我推荐以下方式，更简单易操作：

1. 先跳到你希望多行注释的起始行的行首，这可以使用长指令:n 回车来完成。
2. Ctrl + V: 进入竖选视图模式。
3. 移动光标选中要注释的范围行。
4. 输入大写字母"I"(i的大写，一定要大写)。
   - a. 视图模式输入大写I将进入插入模式
   - b. 此时你输入的任何文本将在每行选中的同一列位置插入
   - c. 这样就能够实现多行注释了。
5. 输入注释的格式//
6. 按退出键位ESC

快速释放多行注释：

1. 先跳到你希望释放的多行注释的起始行的行首，这可以使用长指令:n 回车来完成。
2. Ctrl + v: 进入竖选视图模式。
3. 移动光标选中要释放注释的范围行，选中所有的// 。
4. 直接按d 将所有的// 全部删除。

### 8. Vim的指令宏录制

用宏录制实现使用快捷键快速多行注释：

1. 先使用"Ctrl + v"进入竖选视图模式，选中你想注释几行
2. 按qa来开始录制宏，并将宏存储在寄存器a中。（寄存器大体上就相当于局部变量名，可以是从a~z之间的字母）
3. 执行后续的"I"（大写字母i）以及"//"等操作，这些操作将被录制在寄存器a 中。
4. 再按q 表示结束录制宏
5. 使用指令@a 再次使用录制好的宏命令。

**让宏永久生效:**

如果你想让这个宏在每次打开 Vim 时都可用，你需要将它添加到你的.vimrc文件中。将以下指令：

```c
let @a="I//\<Esc>"
```

添加到文件的末尾，这样@a 指令就是多行注释的永久快捷指令（需要先用视图模式选中注释行）。

### 9. Vim的多窗口操作

Vim允许同时打开多个文件窗口，编辑多个文件。需要用到的指令如下：

| 命令 | 含义 | 备注 |
|---|---|---|
| :split (:sp)[文件名] | 水平分割，默认分割当前文件 | 也可以后面跟一个文件名，表示打开一个新文件 |
| :new [文件名] | 水平分割，会新建一个目标文件 | 如果创建了一个无名文件，可以使用 :saveas 文件名 来保存 |
| :vsplit (:vsp)[文件名] | 垂直分割，默认分割当前文件 | 也可以后面跟一个文件名，表示打开一个新文件 |
| :vnew [文件名] | 垂直分割，会新建一个目标文件 | 如果创建了一个无名文件，可以使用 :saveas 文件名 来保存 |
| ctrl + ww | 循环切换窗口 | 注意是两个ww |
| :wall(:wa) | 保存所有修改过的窗口 |  |
| :qall(:qa) | 退出所有窗口 |  |
| :wqall(:wqa) | 保存并退出所有的窗口 | 还可以用:xall(:xa)来保存退出所有的窗口 |
| :only(:on) | 保留当前窗口，关闭所有其它窗口 |  |

多窗口还是比较常用的，一般还是垂直分割用的多一些好用一些。个人也更喜欢用new 指令来分割窗口，大家课下自行练习选择即可。

### 10. Vim的配置文件

当你使用Vim打开一个文件后，可以输入: ，然后执行下列指令来改变**当前页面**的Vim配置，比如：

1. set number：添加行号
2. colorscheme xx：切换Vim主题配色
3. set hlsearch：高亮显示搜索匹配项
4. ...

这种配置的设置都是一次性的，如果退出文件重新打开配置就失效了。如果希望能永久保存配置，那么就需要编辑Vim的配置文件。

Vim编辑器的配置文件一般都直接放在家目录下，名字为.vimrc ，即~/.vimrc 。

.vimrc 中的rc 是**"running command"**的意思，也就是说：

**每次Vim启动时，Vim 都会读取这个文件，然后将里面的命令执行一遍，从而改变Vim的一些默认配置。**

所以只要把上述的指令都放入这个配置文件中，就可以使得配置永久生效。

注意：

1. 如果没有~/.vimrc 文件，不要惊慌，自己创建一个即可。
2. 作为初学者，不建议大家自己去配置Vim。我们只需要安装Vim-plus就好了，这个Vim插件会帮我们配置好Vim。

### 11. 设置.c文件模板

如果安装了Vim-plus插件，那么它默认使用文件：

~/.vim/plugged/prepare-code/snippet/snippet.c 作为vim*.c 新建.c文件的模板。

于是我们就可以通过修改这个snippet.c 文件的内容，改变默认生成的.c文件的内容，这个操作就非常类似于我们在VS中配置代码模板的操作是一样的。

当下的话，我们建议大家先把模板配置成：

```c
#include <stdio.h>

int main(int argc, char *argv[]){
    printf("Hello world\n");
    return 0;
}
```

注意，如果你直接复制路径找不到这个目录，可以使用指令：

```c
find ~ -name snippet.c
```

在家目录下去寻找snippet.c 文件，然后修改模板文件，若还找不到可直接询问老师。

这个文件模板，你可以随着我们的课程进度的推进，自己自由的进行修改，不用拘泥于老师给定的模板。

# 1. 消息队列

## 1.1 消息队列的原理和特点

>在FreeRTOS中, 任务于任务之间, 以及任务于中断之间可能经常需要进行一些信息的交互和数据的传输. FreeRTOS可以利用队列来实现任务间或者任务和中断间通信.
>
>我们把这种在任务间或者任务于中断间通过队列传递消息的行为称之为**`消息队列`**

>在使用FreeRTOS的消息队列之前, 我们需要知道FreeRTOS中消息队列的特点:
>
>- 消息队列不仅可以用于任务间的消息传递, 还可以用于中断和任务间的信息传递
>- 队列的操作是任务间线程安全的(互斥访问,使用临界区和挂起调度器机制)  (一进入send等函数就会设置临界区)
>- 队列在中断和任务之间也能做到互斥访问, 因为临界区的调用一样能屏蔽低优先级的中断(这个所谓的低优先级, 实际上是指我们在FreeRTOSConfig.h配置的中断优先级)调用
>- 消息队列不依赖于某个任务或者中断而存在, 消息队列需要FreeRTOS为其提供独立的内存空间, 用来存储需要传递的消息, 并且同时存在动态创建和静态创建函数, 动态创建和静态创建的区别在于由谁开辟消息队列所需要的内存空间.
>- 向消息队列发送数据的本质是, 是把数据拷贝到消息队列的内存空间上去 (这个拷贝的本质是按照我们创建消息队列时, 给为一个队列项目指定的最大size为大小拷贝的)
>- 从消息队列读取数据, 本质上是把数据从消息队列的内存上拷贝走
>- 一旦消息队列有信息到来, 会自动从自己记录的xTasksWaitingToReceive(等待消息的任务列表)中删除等待的任务记录, 并且把任务记录转移到**就绪列表**中 .
>- 如果读取数据的时候, 没有数据可读, 并且是阻塞读取, 那么就把当前任务添加到消息队列的等待读取列表xTasksWaitingToReceive
>- 当添加数据的时候, 消息队列满了, 把任务放入xTasksWaitingToSend(等待发送列表), 当有数据被Receive, 则让任务移除等待发送列表(默认选取最高优先级的等待任务), 等待发送
>- 如果是在中断中向消息队列中添加数据的时候, 消息队列满了, 并且添加行为不允许直接覆盖, 添加直接失败, 不支持阻塞模式
>
>```C
>// 在FreeRTOS中不允许中断调用普通的FreeRTOS的API, 能被中断调用的API必须是以FromISR结尾的API函数.
>
>// 注意: 只有优先级小于或等于最大系统调用中断优先级的中断, 调用FromISR结尾的API函数才是安全的 (有些地方说必须在只有优先级小于或等于最大系统调用中断优先级的中断, 才能调用FromISR结尾的API函数.  说法不对)
>// 注意: STM32中配置分组调用:NVIC_PriorityGroupConfig( NVIC_PriorityGroup_4 )
>//   (来自: https://www.FreeRTOS.org/RTOS-Cortex-M3-M4.html  的说明)
>```
>
>````C
>// (queue.h  51)
>typedef struct QueueDefinition   * QueueHandle_t;
>
>// (queue.h  103)
>typedef struct QueueDefinition 
>{
>    int8_t * pcHead;// 对头
>    int8_t * pcWriteTo;// 队尾的下一个位置
>    union
>    {
>        QueuePointers_t xQueue;  // 保存队列信息 (存储队列的对头和队尾指针)
>        SemaphoreData_t xSemaphore; // 保存信号量信息 (信号量也是消息队列实现的)
>    } u;
>    List_t xTasksWaitingToSend;   // 等待发送任务的列表
>    List_t xTasksWaitingToReceive;  // 等待接收数据的任务列表
>    volatile UBaseType_t uxMessagesWaiting; // 队列当中当前队列向的数量(即: 存储是消息数量)
>    UBaseType_t uxLength; // 队列长度(最大消息个数容量)
>    UBaseType_t uxItemSize; // 队列中每隔队列项的最大长度 (即创建消息队列时候的传参)
>    // ...
>} xQUEUE;
>````

# 2. 队列集

>在FreeRTOS中, 队列集(Queue Set)本质是一个队列监听集合(即同时包含多个消息队列的集合),  它允许任务同时监听多个消息队列, 并当监听的任意一个队列有可用时被唤醒, 而不需要分别对所有队列轮询.
>
>```C
>// 例如: 有任务A, 任务B和任务C
>// 1, 使用任务A监听是否有按键触发, 如果有按键触发, 那么就把按键信息存储到队列1
>// 2, 使用任务B监听是否有串口数据, 如果有串口数据到来, 那么把串口数据存储到队列2
>// 3, 任务C在有按键触发的时候向串口打印字符'1', 有串口数据到来, 向串口回复字符'2'; 但是有不想轮训反复以非阻塞的方式判断队列1和队列2( 因为比较浪费开销 )
>
>// 那么我们就可以把, 队列1和队列2放入队列集, 而任务C只需要通过读取队列集的时候, 陷入阻塞; 当两个队列任何一个有数据到来, 都可以唤醒任务C, 去读取和获取数据.
>
>```
>
>**xQueueCreateSet函数**
>
>```C
>// xQueueCreateSet创建队列集
>QueueSetHandle_t xQueueCreateSet(
>UBaseType_t uxEventQueueLength // 队列集中存储的所有队列存储消息的最大总和
>);
>// 返回值: 队列集句柄
>```
>
>**xQueueAddToSet函数**
>
>```C
>// 把消息队列放入队列集
>BaseType_t xQueueAddToSet(
>    QueueSetMemberHandle_t xQueueOrSemaphore,// 队列句柄

## 3.3 互斥信号量

>互斥信号量是一种特殊的二值信号量, 虽然底层也是基于队列实现(固定长度为1), 但是于二值信号量不同的是, 互斥信号量主要用于互斥访问.
>
>- 用于互斥的信号量必须归还, (用于同步的信号量在完成同步之后便丢弃, 不再归还).
>
>```C
>// 假设有一份共享资源, 任务A和任务B都想访问这个资源, 为了做到互斥访问, 我们可以通过互斥信号量的方式来保证访问的互斥性.
>
>// 1, 首先创建互斥信号量
>// 2, 假设任务A 和 任务B都 同时试图获取互斥信号量, 但是只有一个任务能成功获取到信号量, 另外一个任务的获取信号量的行为被阻塞
>// 3, 当其中一个任务访问完成共享资源, 把信号量归还, 则可以触发另外一个等待信号的任务解除阻塞, 获得到信号
>// 4, 在另一个任务获得信号之后, 对共享数据进行操作, 当操作完成, 也需要归还信号量
>```
>
>- 在二值信号量中存在优先级翻转问题, 而互斥信号量通过优先级继承机制, 可以大限度减少优先级翻转.
>
>````C
>// 优先级翻转的说明:
>
>// 假设有任务L (优先级低)
>// 假设有任务M (优先级中等)
>// 假设有任务H (优先级高)
>
>// 当程序一开始执行的时候, M和H因为某些额外的原因陷入阻塞, 所以L得到执行, 当L在执行的时候持有了信号量, 并且需要一段时间的使用, 在L使用的过程中, 突然M和H都陷入就绪, H把L的CPU执行权限抢占, 但是如果H在下程序执行的过程中, 也想获得信号量, 但是此时信号量被L持有, H无法获得该资源, 则陷入阻塞; 当H陷入阻塞之后, M同样抢占了L的执行权限, 而M不需要信号量, 所以M可以正常执行, 当M后续在让出CPU给L执行的时候, L才能继续使用并释放信号量, 至此H才得到执行.
>
>// 从刚才的描述过程中, 我们发现低优先级的M, 先于高优先级的H执行, 我们称这种行为, 为优先级翻转
>````
>
>```C
>// 在互斥信号量中, 是用来一种优先级继承的机制, 去试图规避或者减少优先级翻转问题:
>
>// 如果一个任务在占用一个互斥信号量时没有先释放它已占用的互斥信号量, 可以进一步提升自己的任务优先级.
>// 任务在释放其占有的所有互斥信号量之前, 一直保持最高优先级(以上述示例为例, 任务L会把优先级提升到和H相同优先级, 避免被任务M打断)
>// 当信号量释放之后, 再恢复为原来的优先级
>```

# 4. 事件标志组

## 4.1 原理

>在FreeRTOS中, **事件标志组(Event Groups)** 是一种任务间同步机制.
>
>- 在STM32中, 事件标志组通过维护一个长度为32个bit位的数据, 每一个bit位分别可以代表一个事件是否发生.
>
>````C
>// 在STM32中, 虽然开辟事件标志组是占有32个bit位, 但是只能存储低24位用来标记时间是否发生, 这也就意味着, 事件标志组, 最多只能存储24个事件.
>(事件组由EventGroupHandle_t类型的变量引用。如果configUSE_16_BIT_TICKS设为1，则事件组中存储的位（或标志）数为8； 如果configUSE_16_BIT_TICKS设为 0，则为24。)
>
>// 当对应bit位为1, 表示发生了某个事件; 当对应bit为0, 表示没有发生事件.
>````
>
>- 事件标志组, 比较适合广播通知.
>- 事件标志组, 比较适合一个任务需要在多种条件满足的情况下, 才能执行某个行为的逻辑中.
>
>```C
>// Eg: 比如某些逻辑执行, 需要多个外设设备就绪才能执行
>```

# 5. 任务通知

## 5.1 原理

>在FreeRTOS中的任务通知(Task Notification)是FreeRTOS提供的一种高效的任务间通信方式. 
>
>这是因为: 
>
>- 相比较消息队列/信号量/事件标志组, 任务通知无需动态开辟内存空间, 而是直接在每个任务的TCB中维护通知信息
>
>````C
>(tasks.c  538)
>typedef struct tskTaskControlBlock
>{
>    // ....
>
>    (tasks.c  418)
>    #if ( configUSE_TASK_NOTIFICATIONS == 1 )
>        volatile uint32_t ulNotifiedValue[ configTASK_NOTIFICATION_ARRAY_ENTRIES ];
>        volatile uint8_t ucNotifyState[ configTASK_NOTIFICATION_ARRAY_ENTRIES ];
>    #endif
>
>    // ....
>} tskTCB;
>````
>
>- 不需要数据传递的中间过程, 通知消息将直达目标任务

## 5.2 Give和Take模式

>xTaskNotifyGive函数
>
>```C
>// 用于递增的方式通知任务
>BaseType_t xTaskNotifyGive(
>TaskHandle_t xTaskToNotify // 目标任务句柄
>);
>// 等价于xTaskNotify时使用eIncrement(底层调用的同一个函数)
>
>// 返回值: pdPASS表示发送任务成功
>```
>

>

>);
>// 等价于xTaskNotify时使用eIncrement(底层调用的同一个函数)
>
>// 返回值: pdPASS表示发送任务成功
>```
>
>ulTaskNotifyTake函数
>

## 5.3 传值模式

>xTaskNotify函数
>
>```C
>// 发送通知到目标任务, 并根据eAction指定的模式修改通知值。
>BaseType_t xTaskNotify(
>TaskHandle_t xTaskToNotify,   // 目标任务句柄
>uint32_t ulValue,             // 传递的值
>eNotifyAction eAction         // 任务通知行为
>);
>// 返回值: pdPASS表示发送任务成功
>```
>
>| **模式**     | **枚举值**                  | **行为**                   |
>| ------------ | --------------------------- | -------------------------- |
>| **覆盖模式** | `eSetValueWithOverwrite`    | 覆盖原有的通知值           |
>| **累加模式** | `eSetValueWithoutOverwrite` | 仅在任务未读取通知值时更新 |
>| **按位 OR**  | `eSetBits`                  | 和已有值按位"或"           |
>| **递增模式** | `eIncrement`                | 递增任务通知值(++)         |
>
>xTaskNotifyFromISR函数
>
>````C
>// 在ISR函数中, 用于发送通知到目标任务, 并根据eAction指定的模式修改通知值。
>BaseType_t xTaskNotifyFromISR(
>TaskHandle_t xTaskToNotify,   // 目标任务句柄
>uint32_t ulValue,             // 传递的值
>eNotifyAction eAction,        // 任务通知行为
>BaseType_t *pxHigherPriorityTaskWoken // 任务切换指示, 用于在ISR执行结束后是否进行任务切换
>);
>// 返回值: pdPASS表示发送任务成功
>````
>
>xTaskNotifyWait函数
>
>```C
>// 等待通知, 如果通知到来, 则获取通知值; 可在进入和退出时清除指定的位
>BaseType_t xTaskNotifyWait(
>uint32_t ulBitsToClearOnEntry,  // 进入函数时清除的位
>uint32_t ulBitsToClearOnExit,   // 退出函数时清除的位
>uint32_t *pulNotificationValue, // 存储通知值
>TickType_t xTicksToWait         // 超时时间
>);
>// 返回值:pdPASS收到通知, pdFAIL表示超时
>```
>
